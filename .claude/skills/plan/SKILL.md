# /plan — 实施规划

用户通过 `/plan` 触发时，**必须**按以下流程执行，不得跳过任何阶段。

## 执行流程

### 阶段一：需求理解（探索优先）

在开始规划前，先探索与任务相关的代码上下文：
- 读取相关路由、模型、服务文件
- 了解现有约定（命名规范、目录结构、技术栈）
- 识别依赖项和潜在风险点

### 阶段二：规划文档生成

使用 **everything-claude-code:planner** 子代理，输出以下内容：

1. **需求摘要**：用 1-3 句话描述目标
2. **技术方案**：关键设计决策及备选方案对比
3. **实施阶段**：按优先级排序的阶段列表，每阶段包含：
   - 目标描述
   - 涉及文件（精确到路径）
   - 完成标准（可验证的 Acceptance Criteria）
4. **风险评估**：潜在的技术风险和缓解策略
5. **测试策略**：对应的单元/集成/E2E 测试覆盖计划

### 阶段三：文档同步（强制）

规划完成后，**必须**将文档保存至：

```
document/YYYYMMDD_[任务描述]_plan.md
```

格式遵循项目规范（`01-工作流与语言规范.md` 第三节）。

### 阶段四：任务列表同步

使用 `TodoWrite` 将各阶段任务转为可追踪的 Todo 项，在执行过程中实时标记完成状态。

## 输出语言

全程简体中文，技术术语保留原文。

## 注意事项

- 规划阶段**不写代码**，只输出计划
- 发现盲点或歧义时，先列出问题再继续
- 规划文档一旦生成，立即同步到 `document/` 目录，不得遗漏
