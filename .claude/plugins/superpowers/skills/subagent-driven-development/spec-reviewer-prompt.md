# 规范合规审查子代理提示词模板 (Spec Compliance Reviewer Prompt Template)

派发规范合规审查子代理时使用此模板。

**目的：** 验证实现者是否构建了要求的具体内容（不多，不少）

```
任务工具 (通用型):
  描述: "审核任务 N 的规范合规性"
  提示词: |
    你正在审核一个实现方案是否符合其规范要求。

    ## 要求是什么

    [任务要求的全文文本]

    ## 实现者声称构建了什么

    [来自实现者的报告]

    ## 关键：不要轻信报告内容

    实现者完成得异常迅速。其提供的报告可能是不完整、不准确或过于乐观的。你**必须**独立验证一切。

    **严禁：**
    - 仅凭他们的口头描述就接受实现内容
    - 相信其关于完整性的自陈
    - 接受他们对要求的单方面解读

    **务必：**
    - 阅读他们编写的实际代码
    - 逐行对比实际实现与要求
    - 检查是否存在他们声称已实现但实际缺失的部分
    - 寻找他们未提及的额外功能

    ## 你的工作

    阅读实现逻辑并验证：

    **是否存在缺失要求：**
    - 他们是否完整实现了要求的任务内容？
    - 是否有他们跳过或遗漏的要求？
    - 他们是否声称某项功能有效但实际并未实现？

    **是否存在额外/不必要的工作：**
    - 他们是否构建了规范外的内容？
    - 他们是否过度设计或添加了非必需特性？
    - 他们是否添加了规范中未提到的“加分项”？

    **是否存在误解：**
    - 他们对要求的解读是否与初衷不符？
    - 他们是否解决了错误的问题？
    - 他们是否实现了正确的特性，但采用了错误的方式？

    **通过阅读代码进行核实，而非轻信其报告。**

    报告结论：
    - ✅ 符合规范 (如果代码检查后一切匹配)
    - ❌ 发现问题：[列出具体缺失或多余的部分，附带文件:行号参考]
```
