# 完成开发分支 (Finishing a Development Branch)

## 概览

通过呈现清晰的选项并处理选定的工作流，引导开发工作的圆满完成。

**核心原则：** 验证测试 ——> 呈现选项 ——> 执行选择 ——> 执行清理。

**开始时宣布：** “我正在使用 finishing-a-development-branch 技能来完成这项工作。”

## 流程步骤

### 第 1 步：验证测试

**在呈现选项之前，必须验证测试通过：**

```bash
# 运行项目的测试套件
npm test / cargo test / pytest / go test ./...
```

**如果测试失败：**
```
测试失败（包含 <N> 个失败项）。在完成前必须修正：

[展示失败详情]

在测试通过之前，无法进行合并或创建 PR。
```

停止操作。不要进入第 2 步。

**如果测试通过：** 继续进入第 2 步。

### 第 2 步：确定基准分支 (Base Branch)

```bash
# 尝试常见的基准分支
git merge-base HEAD main 2>/dev/null || git merge-base HEAD master 2>/dev/null
```

或者询问：“该分支是从 main 分支切出的 —— 这样对吗？”

### 第 3 步：呈现选项

准确呈现以下 4 个选项：

```
实现已完成。你希望接下怎么做？

1. 在本地合并回 <base-branch>
2. 推送并创建一个拉取请求 (Pull Request)
3. 保持分支现状（我稍后会处理）
4. 放弃此项工作

请选择哪一项？
```

**不要添加额外解释** —— 保持选项简洁。

### 第 4 步：执行选择

#### 选项 1：本地合并

```bash
# 切换到基准分支
git checkout <base-branch>

# 拉取最新代码
git pull

# 合并功能分支
git merge <feature-branch>

# 在合并结果上验证测试
<测试命令>

# 如果测试通过
git branch -d <feature-branch>
```

然后：清理工作树 (第 5 步)。

#### 选项 2：推送并创建 PR

```bash
# 推送分支
git push -u origin <feature-branch>

# 创建 PR
gh pr create --title "<标题>" --body "$(cat <<'EOF'
## 摘要
<用 2-3 个要点描述改动内容>

## 测试计划
- [ ] <验证步骤>
EOF
)"
```

然后：清理工作树 (第 5 步)。

#### 选项 3：保持现状

报告： “正在保留分支 <名称>。工作树保存在 <路径>。”

**不要清理工作树。**

#### 选项 4：放弃工作

**首先进行确认：**
```
这将永久删除：
- 分支 <名称>
- 所有提交记录: <commit-list>
- 位于 <路径> 的工作树

请输入 'discard' 以确认。
```

等待准确的确认输入。

如果已确认：
```bash
git checkout <base-branch>
git branch -D <feature-branch>
```

然后：清理工作树 (第 5 步)。

### 第 5 步：清理工作树 (Cleanup Worktree)

**对于选项 1, 2, 4：**

检查是否位于工作树中：
```bash
git worktree list | grep $(git branch --show-current)
```

如果是：
```bash
git worktree remove <工作树路径>
```

**对于选项 3：** 保留工作树。

## 快速参考

| 选项 | 合并 | 推送 | 保留工作树 | 清理分支 |
|--------|-------|------|---------------|----------------|
| 1. 本地合并 | ✓ | - | - | ✓ |
| 2. 创建 PR | - | ✓ | ✓ | - |
| 3. 保持现状 | - | - | ✓ | - |
| 4. 放弃 | - | - | - | ✓ (强制) |

## 常见错误

**跳过测试验证**
- **问题：** 合并了损坏的代码，或者创建了失败的 PR。
- **修正：** 在提供选项之前始终验证测试。

**开放式提问**
- **问题：** “我下一步该做什么？” —— 含义模糊。
- **修正：** 准确呈现上述 4 个结构化选项。

**自动清理工作树**
- **问题：** 在可能还需要工作树时将其移除（选项 2, 3）。
- **修正：** 仅针对选项 1 和 4 进行清理。

**放弃工作时未经确认**
- **问题：** 意外删除了工作成果。
- **修正：** 要求手动输入 "discard" 进行确认。

## 警示信号 (Red Flags)

**严禁执行以下操作：**
- 在测试失败的情况下继续。
- 在未验证合并结果测试的情况下进行合并。
- 在未经确认的情况下删除工作。
- 在未经明确要求的情况下进行强制推送 (Force-push)。

**务必执行：**
- 在提供选项之前验证测试。
- 准确呈现 4 个选项。
- 为选项 4 获取输入确认。
- 仅为选项 1 和 4 清理工作树。

## 集成

**由以下技能调用：**
- **subagent-driven-development** (第 7 步) —— 在所有任务完成后。
- **executing-plans** (第 5 步) —— 在所有批次完成后。

**配合项：**
- **using-git-worktrees** —— 清理由该技能创建的工作树。
