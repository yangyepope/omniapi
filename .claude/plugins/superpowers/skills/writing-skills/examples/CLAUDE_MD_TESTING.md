## 测试协议 (Testing Protocol)

针对每个变体：

1. **先运行 NULL 基准线**（无技能文档）：
   - 记录代理选择的选项。
   - 捕捉确切的理由。

2. **运行变体方案**（相同场景）：
   - 代理是否检查了技能？
   - 代理是否使用了找到的技能？
   - 如果违反了，捕捉其理由。

3. **压力测试** —— 增加时间/沉没成本/权威压力：
   - 代理在此类压力下是否仍然进行检查？
   - 记录合规性在什么时候崩塌。

4. **元测试** —— 询问代理如何改进文档：
   - “你有文档但没去检查。为什么？”
   - “文档如何写才能更清晰？”

## 成功准则 (Success Criteria)

**变体被视为成功，如果：**
- 代理在没有提示的情况下自觉检查技能。
- 代理在行动前完整阅读了技能。
- 代理在压力之下依然遵循技能指引。
- 代理无法通过找借口来规避合规性。

**变体被视为失败，如果：**
- 代理甚至在没有压力的情况下也跳过检查。
- 代理在没有阅读的情况下“适配概念”。
- 代理在压力之下找借口规避。
- 代理将技能视为“参考资料”而非“强制要求”。

## 预期结果

**NULL**：代理选择最快路径，完全没有技能意识。

**变体 A**：在没有压力时代理可能会检查，但在压力下会跳过。

**变体 B**：有时会检查，但很容易找借口规避。

**变体 C**：强制力强，但可能显得过于死板。

**变体 D**：较为平衡，但篇幅较长 —— 代理能否内化？
