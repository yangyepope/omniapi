# 规则组织母版(跨项目通用)

> **本文件定义所有项目的规则存放模式**:CLAUDE.md 保持薄,专项规则放 `.claude/rules/*.md` 并用 `paths:` frontmatter 按需加载。参考实现:security-platform 项目。

## 分工铁律

| 放哪 | 放什么 | 加载 |
|---|---|---|
| 根 `CLAUDE.md` | 项目一句话、常用命令、少量全局硬规则、目录结构 | 每次会话必载,**保持薄**(<60 行) |
| `.claude/rules/NN-主题.md` 无 frontmatter | 全局流程规范(语言/日志/文档沉淀) | 每次会话必载,谨慎新增 |
| `.claude/rules/NN-主题.md` 带 `paths:` | 专项规则(某服务/某语言/某文件类型) | 只在触碰匹配文件时载入 |
| `.claude/reference/` | 参考资料、跨项目母版原件、他工具规则 | **不自动载入**,按需查阅 |

## 新建规则文件模板

```markdown
---
paths:
  - "backend/**"        # glob 可多条、可跨目录、可按扩展名("**/*.sql")
---

# NN-主题名

(规则正文:短句 bullet,给出 ❌/✅ 对照;违例检测尽量附可执行 tripwire 命令)
```

## 新增规则前自查

1. 已有规则能否**扩展**?能就加条目,不新建文件(单一真相源,禁复制内容到多处)
2. 编号 `NN-` 递增;确定最小 `paths` 范围——覆盖面宁窄勿宽,全局规则是例外不是默认
3. 从存量代码提炼的规则,附「存量缺口」清单:新代码 100% 合规、触碰即修、不专项重构

## 反模式(踩过的坑)

- ❌ Cursor 式 frontmatter(`globs:` / `alwaysApply:`)——Claude Code 不识别,等于全局注入;只用 `paths:`
- ❌ 子目录 CLAUDE.md 与 rules 并存写同一内容——双份注入
- ❌ 同一规则中英/多副本共存(如 `~/.claude/rules/` 与项目内同文件)——重复注入,只留一份
- ❌ 参考资料(指令集文档/母版原件/他工具规则)放 `.claude/rules/` 下——会被无差别注入,放 `.claude/reference/`
