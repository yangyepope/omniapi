## 一、路由 async/sync 决策(本项目最容易犯错的一条)

**本项目默认写 `def` 同步路由**(FastAPI 自动跑线程池,同步 Session 天然安全)。

| 路由里做什么 | 用什么 |
|---|---|
| 走同步 Session 查库(本项目绝大多数) | `def`(线程池,安全) |
| 真正的 awaitable I/O(httpx.AsyncClient 等) | `async def` + `await` |
| async 路由里必须调同步库 | `await run_in_threadpool(fn, ...)` |
| CPU 密集(>50ms) | Celery worker,不进路由 |

```python
# ❌ 禁止:async 路由里直接用同步 Session/requests/time.sleep
#    同步调用会冻结整个事件循环,所有请求一起卡死
@router.post("/collect")
async def collect(session: SessionDep):      # async + 同步 Session = 事故
    session.exec(...)                        # 阻塞事件循环

# ✅ 改法一(首选):没有真正的 await 就别写 async
@router.post("/collect")
def collect(session: SessionDep):
    session.exec(...)                        # 线程池里跑,安全

# ✅ 改法二:确实需要 await 外部服务时,同步部分裹进线程池
@router.post("/collect")
async def collect(session: SessionDep):
    data = await httpx_client.get(...)              # 真 async I/O
    await run_in_threadpool(save_to_db, session, data)  # 同步 DB 进线程池
```

**Tripwire(可直接跑)**:async 路由里用同步 Session 的违例检测——

```bash
grep -rn "async def" backend/app/api/routes/*.py -A6 | grep "SessionDep" && echo "❌ 发现 async 路由注入同步 Session" || echo "✅ 通过"
```

## 二、Pydantic v2 惯用法

- 校验交给内置类型与 `Field`,不手写 validator 能解决的事:

```python
from enum import StrEnum
from pydantic import BaseModel, EmailStr, Field

class Source(StrEnum):                       # 枚举一律 StrEnum,序列化即字符串
    MANUAL = "manual"
    DISCOVERY = "discovery"

class ServiceCreate(BaseModel):
    name: str = Field(min_length=1, max_length=128)
    email: EmailStr | None = None
    port: int = Field(ge=1, le=65535)
```

- **禁** `Field(ge=18, default=None)`(约束与默认值冲突);可选写 `int | None = Field(default=None, ge=18)`。
- **禁** `json_encoders`(v2 已废);自定义序列化用 `@field_serializer` / `PlainSerializer`。
- **禁**用裸 `dict` 传核心数据(02 铁律已定);跨层传递一律 Pydantic/SQLModel 模型。
- 配置按域拆分 `BaseSettings`(env_prefix 区分),不要一个 `Settings` 装全站——本项目 `app/core/config.py` 新增配置时按此收敛。

## 三、依赖注入:校验下沉到 Depends

- **统一 `Annotated[T, Depends(...)]` 写法**(项目已有 `SessionDep`/`CurrentUser`,沿用):

```python
# ✅ 需要查库的校验写成依赖,可复用、可链式组合
def valid_service_id(service_id: uuid.UUID, session: SessionDep) -> Service:
    service = session.get(Service, service_id)
    if not service:
        raise ServiceNotFound()              # 领域异常,全局拦截器转响应
    return service

ServiceDep = Annotated[Service, Depends(valid_service_id)]

# ✅ 链式:所有权校验复用上面的依赖
def valid_owned_service(service: ServiceDep, user: CurrentUser) -> Service:
    if service.owner_id != user.id:
        raise NotOwner()
    return service
```

- 依赖在**同一请求内自动缓存**:多个依赖共用 `valid_service_id` 不会重复查库——放心拆小、组合。
- 多个路由取同一路径参数时**用同一个参数名**(统一 `service_id`),依赖才能跨端点复用。

## 四、数据库命名与 SQL-first

- 表名 `lower_snake` 单数(`service`、`api_key`);同域表加前缀(`replay_task`、`replay_result`)。
- 时间列 `_at`(datetime)/`_date`(date) 后缀;同一实体的外键列名全库一致(永远 `service_id`,不出现 `svc_id` 混用)。
- 索引/约束命名走 `MetaData(naming_convention=...)` 统一模板(与 04 铁律的 `uq_<表>_<字段>` 呼应),Alembic autogenerate 才不会反复误报。
- **SQL-first**:聚合/join/JSON 拼装尽量在 Postgres 做(`func.json_build_object` 等),Pydantic 只做响应校验,不做数据变换。

## 五、后台任务:BackgroundTasks vs Celery 分界

| 用 `BackgroundTasks` | 用 Celery(本项目已有 worker) |
|---|---|
| <1 秒、丢了无所谓(发邮件通知、记一行日志) | 秒级以上、要重试/可见性(回放、扫描、采集入库) |
| 与请求同进程,worker 挂了就丢 | 需要定时/限流/独立资源池 |

**禁止**用 BackgroundTasks 做关键业务——响应发出后同进程执行、无重试、无痕迹丢失。
Celery Task 内的写操作规则见 04 铁律(行锁/Upsert/幂等),此处不重复。

## 六、测试

- 覆盖外部依赖用 `app.dependency_overrides[dep] = fake`,**不要 monkeypatch 内部函数**:

```python
@pytest.fixture(autouse=True)
def _override_auth():
    app.dependency_overrides[get_current_user] = fake_superuser
    yield
    app.dependency_overrides.clear()
```

- 集成测试打**真实 DB**(项目已有 test 库链路),只 override 认证与外部服务;mock 掉 DB 的"集成测试"不算数。
- 新增 async 路由的测试用 `httpx.AsyncClient + ASGITransport`;存量同步 `TestClient` 用例不动。

## 七、反模式速查(review 触发即改)

| 反模式 | 改法 |
|---|---|
| `async def` 路由里 `requests.get` / `time.sleep` / 同步 Session | `def` 路由,或 `httpx.AsyncClient` / `run_in_threadpool` |
| `from jose import jwt` | `import jwt`(PyJWT) |
| `Depends(x)` 写在默认参数位 | `Annotated[T, Depends(x)]` |
| 路由里裸 `try-except Exception` | 领域异常 + 全局拦截(02 铁律) |
| BackgroundTasks 跑关键任务 | Celery |
| `json_encoders` | `@field_serializer` |
| 路由里先查再判再写 | 04 铁律:Upsert / 行锁 |
| mock DB 的集成测试 | 真 DB + dependency_overrides |
| 跨域深层 import(`from app.services.replay.core.x import y`) | 模块级 import(`from app.services import replay`) |
