# 03-前端架构铁律 (Frontend Core)

本文档定义了 SecurityPlatform 前端的统一架构标准与技术选型，并在 `ecc/typescript` 通用编码标准基础上执行。

---

## 一、 技术栈核心 (Tech Stack V4)

AI 助手在前端开发中必须严格遵循以下版本：
- **React 19**: 优先采用最新 Hooks 和异步组件特性。
- **Vite 7**: 构建引擎。
- **TanStack Router**: **强类型路由**。所有路由必须基于文件自动推导。
- **Tailwind CSS v4**: 全新的 CSS 变量驱动样式。严禁手写普通 `.css` 文件。
- **Biome**: 唯一的 Linting & Formatting 工具 (`bun run lint`)。

---

## 二、 组件开发规范 (UI Architecture)

- **shadcn/ui 优先**: 所有的基础交互组件（弹窗、按钮、下拉菜单）必须基于 `shadcn/ui`。
- **单一职责**: 每个组件文件不得超过 **150 行**。逻辑过重必须拆分。
- **lucide-react**: 唯一的图标库标准。
- **响应式 (Mobile-First)**: 默认以移动端为基准，使用 `md:`, `lg:` 进行大屏适配。
- **暗黑模式**: 使用 `next-themes` 和 CSS 变量驱动主题切换。

---

## 三、 状态与数据管理

- **异步状态 (Server State)**: 必须使用 **TanStack Query (React Query)**。禁止在 `useEffect` 里手动 `fetch`。
- **URL 状态驱动**: 分页、搜索关键词等参数必须同步到路由的 `search` params。

---

## 四、 前后端契约 (Contract-First)

- **hey-api/openapi-ts**: 严禁手动编写 API 调用层。必须通过脚本自动生成客户端。
- **类型安全**: 直接使用由 OpenAPI Schema 生成的 TypeScript 类型定义，禁止手动声明后端返回数据的 `interface`。

---

## 五、 表单与校验

- **react-hook-form**: 唯一的表单管理库。
- **zod & resolver**: 强制使用 `zod` 定义 Schema 校验，通过 `@hookform/resolvers/zod` 进行桥接。

---

## 六、 错误与反馈逻辑

- **sonner**: 唯一的全局提示方式。
- **React Error Boundary**: 所有的复杂功能块必须包裹在错误边界中，提供降级降级 UI。
- **极致注释**: 前端业务逻辑同样必须执行“**逐行中文注释**”，解释 Why over What。
