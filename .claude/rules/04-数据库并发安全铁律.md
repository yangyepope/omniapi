# 04-数据库并发安全铁律 (DB Concurrency Safety)

本文档源于生产环境中因"查-判-写"竞态条件导致 `total_traffic_count = 0`
的真实故障，作为 `02-后端架构铁律.md` 的强制补充，具有同等优先级。

---

## 一、 模型层：约束优先原则 (Constraint-First)

> **铁律**：任何业务上"不能重复"的字段组合，**必须在模型第一次定义时就声明唯一约束**，
> 而不是依靠应用层逻辑保证。

### 强制执行

```python
# [Why]：在 SQLModel 模型中声明 __table_args__，alembic autogenerate 会自动检测；
# 如果忘记加，CI 的 alembic check 会报错，杜绝事后补救。
class ApiEndpoint(SQLModel, table=True):
    __table_args__ = (
        UniqueConstraint(
            "method", "path", "service_name",
            name="uq_apiendpoint_method_path_service"
        ),
    )
```

### 新建模型 / 新增字段 PR 检查清单

在提交任何涉及 `SQLModel` 模型的 PR 前，必须逐项确认：

- [ ] 业务唯一键组合是否已声明 `UniqueConstraint`？
- [ ] 是否存在"查 → 判断是否存在 → 写"三步逻辑？若有，**必须改用 Upsert 或行锁**
- [ ] 计数器字段更新是否使用 SQL 表达式（`col + 1`）而非 Python 赋值？
- [ ] Celery / 异步 Task 中的写操作是否通过 `with_for_update()` 持有行锁？
- [ ] 对应的 Alembic 迁移是否包含了约束定义？

## 二、 应用层：禁用"查-判-写"反模式

### 禁止（Anti-Pattern）

```python
# [Why]：三步之间存在不可消除的并发窗口，多个 Worker 同时读到 None 后各自插入，
# 导致重复记录和计数器丢失更新。
existing = session.exec(select(Foo).where(...)).first()  # 读
if not existing:                                          # 判
    session.add(Foo(...))                                 # 写  ← 危险窗口
    session.flush()
```

### 强制（Upsert 模式）

```python
# [Why]：ON CONFLICT DO NOTHING 是数据库原子操作，无论多少并发 Worker 同时执行，
# 只有一条记录会被插入，彻底消除竞态窗口。
# 详细代码模板见 skill: db-concurrency-guard
from sqlalchemy.dialects.postgresql import insert as pg_insert

stmt = pg_insert(Foo).values(...).on_conflict_do_nothing(
    index_elements=["col_a", "col_b"]
).returning(Foo.id)
```

### 计数器更新：禁止 Python 级加法

```python
# 禁止：读-加-写，并发下会丢失更新
endpoint.total_traffic_count += 1

# 强制：SQL 表达式原子更新
from sqlalchemy import update
session.exec(
    update(ApiEndpoint)
    .where(ApiEndpoint.id == endpoint_id)
    .values(total_traffic_count=ApiEndpoint.total_traffic_count + 1)
)
```

## 三、 测试层：并发安全必须有测试覆盖

以下三类测试**必须**存在，缺失视为 PR 不完整：

| 测试类型 | 位置 | 验证目标 | 运行时机 |
|---------|------|---------|---------|
| **并发写入测试** | `backend/tests/functional/` | 多 Worker 同时写入不产生重复记录 | 每次 PR |
| **计数一致性测试** | `backend/tests/functional/` | 冗余计数器与实际行数吻合 | nightly CI |
| **E2E 数值断言** | `frontend/tests/` | UI 展示数值 > 0 且与详情页行数匹配 | 每次 PR |

> 详细测试代码模板见 Skill：`db-concurrency-guard`（路径：`.claude/skills/db-concurrency-guard/SKILL.md`）

## 四、 Code Review 触发条件

**遇到以下任意一项，必须停下来对照本文档全面审查：**

1. 新增 `SQLModel` / `SQLAlchemy` 模型类
2. 新增 `@celery_app.task` 或异步后台任务
3. 代码中出现 `.first()` 后紧跟 `if not xxx` 再 `session.add`
4. 代码中出现 `obj.count += 1` 形式的计数器操作
5. 新增 `alembic/versions/` 迁移文件（验证约束是否完整）
