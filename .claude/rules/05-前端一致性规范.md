# 05-前端一致性规范 (Frontend Consistency)

> 本文件是 `母版/ts-fullstack-consistency-template.md` 针对**本项目真实栈**的提炼落地版。
> 母版示例栈为 Next.js + tRPC(T3 系),本项目为 **Vite 7 + React 19 + TanStack Router +
> TanStack Query + hey-api/openapi-ts + shadcn/ui + Tailwind v4 + Biome**。
> 纪律不变,路径与术语全部按本项目映射。与 `03-前端架构铁律.md` 冲突时以 03 为准。
>
> **唯一目的:同一种 UI 模式,全站只有一种实现。**
> 任何"分页 A 页一种样式、B 页另一种样式""时间这里 `2026-07-02`、那里 `07/02/2026`"
> "颜色东一个 `#3b82f6` 西一个 `blue-500`"都视为 bug。

## 一、钦定位置表(单一真相源,只准 import,禁止重造)

| 资产 | 钦定位置(本项目真实路径) | 铁律 |
|---|---|---|
| shadcn 原语 | `frontend/src/components/ui/*` | 已有 24 个(button/dialog/table/badge/pagination/skeleton/sonner…);弹窗/下拉/tooltip/tabs 一律用它,不手写 |
| 跨功能共享组件 | `frontend/src/components/Common/*` | 已有 DataTable/ErrorComponent/NotFound 等;每种模式**只有一个文件** |
| 功能私有组件 | `frontend/src/components/<Feature>/*` | 如 `services/`、`traffic/`;仅当确实不可复用 |
| 设计 token | `frontend/src/index.css` 的 `@theme` 块 | 组件里只引用语义 token,见 §四 |
| `cn()` 等类名工具 | `frontend/src/lib/utils.ts` | — |
| API 错误提取/提示 | `frontend/src/utils.ts`(`handleError`) | 各页不得自拼错误解析逻辑 |
| 格式化(时间/数字) | `frontend/src/lib/format.ts` | **尚未存在,首次需要时在此创建**,见 §五 |
| 状态徽章 | `frontend/src/components/Common/StatusBadge.tsx` | **尚未存在,首次需要时创建**;映射与渲染分离,见 §五 |
| API 客户端与类型 | `frontend/src/client/*`(hey-api 生成) | **禁止手改**;后端 Schema 变更后跑 `bun run generate-client` 重新生成;禁止手写后端返回数据的 `interface` |
| i18n 文案 | `frontend/src/locales/{en-US,zh-CN}/` | 禁止 JSX 硬编码可见文案 |
| 表单校验 Schema | zod(`@hookform/resolvers/zod` 桥接) | 约束须与后端 Pydantic `Field(...)` 对齐 |

### 动手前的三步决策

```
需要一个 UI 模式 / 一段格式化 / 一个校验?
  ├─ 钦定位置已有 ────────→ 直接 import
  ├─ 有但差一个选项 ──────→ 给它加 prop(扩展),不要复制改名
  └─ 完全没有 ────────────→ 在钦定位置新建"一个",供全站复用(不要写在页面里)
```

## 二、单向依赖(提炼自 bulletproof-react)

代码只能**单向流动**,反向 import 视为架构违例:

```
共享层 ──────────→ feature 层 ─────────→ 应用层
ui/ Common/          components/<Feature>/    routes/
providers/ layout/   (services、traffic、
lib/ hooks/ client/  Admin、Dashboard…)
utils.ts
```

- **共享层**(`ui/`、`Common/`、`providers/`、`layout/`、`lib/`、`hooks/`、`client/`)不得 import 任何 feature 或 route;
- **feature 之间禁止互相 import**(`components/services/` 不得 import `components/traffic/`)——需要共用的东西下沉到 `Common/` 或 `lib/`,或在 `routes/` 层组合;
- **routes/** 可以 import 一切,自己只做组合。
- 避免 barrel 文件(`index.ts` 全量再导出)——妨碍 Vite tree-shaking,直接 import 具体文件。

**Tripwire(可直接跑,已验证)**:检测 feature 互相引用——

```bash
cd frontend/src/components && for f in */; do f=${f%/}; \
  { [ "$f" = "ui" ] || [ "$f" = "Common" ] || [ "$f" = "providers" ] || [ "$f" = "layout" ]; } && continue; \
  grep -rln "components/$f" --include="*.tsx" --include="*.ts" . | grep -v "^./$f/"; done | sort -u
# 输出为空 = 通过;有输出 = 列出的文件跨 feature 引用了别的 feature
```

## 三、组件化与路由

- **路由文件(`src/routes/**`)只做组合**:取数交给 TanStack Query hook、细节交给子组件;不塞表格/表单/校验逻辑。
- 单组件文件 ≤ **150 行**(03 铁律,严于母版的 200 行),逻辑过重拆 hook / 纯函数。
- 组件文件命名沿用**现有 PascalCase**(`DataTable.tsx`),不引入母版的 kebab-case——与存量风格一致优先。

## 四、视觉 token(消灭乱配色/乱字号)

- **颜色**:只用语义 token(`bg-primary` / `text-muted-foreground` / `border-destructive`…)。禁止裸 `#hex`、`rgb()`、`bg-[#3b82f6]` 任意值类,禁止直接用调色板阶(`blue-500`)。
- **字号**:只用阶梯(`text-xs/sm/base/lg/…`);禁止 `text-[13px]`、`style={{ fontSize }}`。
- **间距**:4/8px 节奏(`p-2` `gap-4`);禁止 `mt-[13px]`。
- **圆角**:`rounded-sm/md/lg/xl`(已在 `@theme` 由 `--radius` 派生)。
- **图标**:只用 lucide-react(03 铁律);存量 react-icons 触碰到时逐步迁移,不新增。
- 新 token 一律加进 `src/index.css` 的 `@theme`,不在组件里造。

## 五、数据展示格式

### 5.1 唯一 formatter:`src/lib/format.ts`

- 首次需要时创建,底层用 `Intl.*`,接收 locale(与 react-i18next 当前语言联动)。
- **禁止**组件里出现 `new Date().toLocaleDateString()`、手拼 `${y}-${m}-${d}`、裸 `Intl.*`。
- UTC 存储、按用户 locale 渲染;日期用 `<time dateTime={iso}>` 语义标签。

### 5.2 枚举 → 徽章:映射与渲染分离

- 映射:typed record 就近于 feature(如 `SERVICE_STATUS: Record<Status, {label, variant}>`)。
- 渲染:全站唯一 `<StatusBadge>`(基于 `ui/badge.tsx`),任何页面同一状态长相一致。
- 现有 `services/SourceBadge.tsx`、`MethodBadge.tsx` 属于 feature 私有映射,可保留;但**新增状态徽章不得再各写各的渲染**。

## 六、数据流(TanStack Query + hey-api)

- 取数一律 TanStack Query;**禁止 `useEffect` 手动 fetch**(03 铁律)。
- 分页/搜索/筛选参数必须同步到路由 `search` params(TanStack Router 强类型 search)。
- mutation 成功后必须 `queryClient.invalidateQueries(...)` 使相关查询失效;成功/失败提示统一 sonner `toast`。
- 表单:react-hook-form + `zodResolver`;zod 约束严格对齐后端 Pydantic 定义(Zod-Pydantic-Bridge)。

## 七、四态纪律

每个异步视图必须有四态,**不许只写 success**:
- `loading` → 复用 `ui/skeleton.tsx`
- `empty` → 共享空状态(首次需要时建 `Common/EmptyState.tsx`)
- `error` → `Common/ErrorComponent.tsx` / react-error-boundary 包裹复杂功能块
- `success` → 正常渲染

破坏性操作统一走共享确认框(首次需要时基于 `ui/dialog.tsx` 建 `Common/ConfirmDialog.tsx`,现 `UserSettings/DeleteConfirmation.tsx` 属 feature 私有,新需求不得再复制一份)。

## 八、完成定义(前端改动提交前自查)

- [ ] 用到的模式都来自 §一钦定位置,无重造/复制
- [ ] 无裸色值、无调色板阶、无任意值字号/间距
- [ ] 时间/数字格式化走 `lib/format.ts`(若本次触及)
- [ ] 异步视图四态齐全;反馈走 sonner;破坏性操作走共享确认框
- [ ] 路由文件只做组合;组件 ≤150 行
- [ ] API 类型来自 `src/client/`,无手写后端 interface
- [ ] 可见文案走 i18n,无硬编码
- [ ] `bun run lint`(Biome)通过
