# 2026-04-05 修复重放“状态 0”显示及侧边栏布局问题

## 现象 (Symptom)
1. **报错模糊**: 当变体所在服务不可达时，界面仅显示“失败 0”，用户无法判断是连接超时、拒绝连接还是 DNS 故障。
2. **布局冗余**: 变体详情侧边栏打开时，会出现两个纵向滚动条，背景页面仍可滚动。
3. **内容局促**: 新增的“连接故障审计”区域文字过小（10px），排查项 A/B 在窄屏下相互挤压，难以阅读。

## 调查 (Investigation)
1. **后端审计**: `app/services/replay.py` 仅捕获了通用 Exception，未对 `httpx` 的网络层异常做语义化转换。
2. **溢出追踪**: 侧边栏使用了 `fixed` 定位，但未在打开时对 `document.body` 执行滚动锁定（Scroll Lock）。
3. **UI 走查**: 诊断框使用了 `grid-cols-2` 且字号极小，导致在 `max-w-2xl` 的容器内显示效果不佳。

## 根因 (Root Cause)
- **底层错误未分类**: 网络层异常被映射到了统一的 HTTP 0。
- **全局 CSS 逻辑缺失**: 侧滑组件缺乏对父级容器溢出的控制。
- **设计过度保守**: 采用了过小的字号和过紧的网格。

## 修复 (The Fix)
### 1. 后端语义化 (Backend)
- 修改 `backend/app/services/replay.py`：捕获 `httpx.ConnectError` 和 `httpx.TimeoutException`，并将诊断摘要存储在 `last_response_body` 中。

### 2. 前端显示优化 (Frontend)
- **状态映射**: `VariantCard` 增加状态映射逻辑，将 0 转化为“连接失败”或“请求超时”。
- **滚动锁定**: 在 `index.tsx` 中添加 `useEffect` 钩子，当 `selectedVariant` 存在时锁死 `body` 滚动，解决双滚动条问题。
- **UI 升级**: 
    - 字体从 `10px` 提升至 `12px/14px`。
    - 将 A/B 排查项改为纵向卡片流，提高易读性。
    - 增加内边距和圆角（`rounded-[3rem]`），强化视觉区块。

## 验证 (Proof)
1. **模拟故障**: 手动触发一次指向不存在域名的重放，界面准确显示“连接失败”及 A/B 排查建议。
2. **交互核验**: 侧边栏开启后，背景页面无法自由滚动，右侧仅保留一个主滚动条。
3. **视觉测试**: 诊断文字在小屏幕下依然清晰，无重叠现象。
