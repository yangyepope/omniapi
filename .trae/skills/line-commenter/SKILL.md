# 逐行注释助手（中文）

## 目标

对用户指定的文件/代码片段进行“逐行中文详细注释”，帮助读者理解每一行的用途、输入输出、关键约束与潜在坑点。

## 何时调用

- 用户要求“每行加详细注释 / 逐行注释 / 代码每段加注释 / 越详细越好”
- 用户希望“以后写代码默认都加逐行注释，不想每次重复说”
- 用户正在改某个文件，并要求补齐/统一注释风格

## 产出要求（强约束）

1. 只做“加注释/整理注释”的改动，不改变业务逻辑与行为
2. 注释语言：中文；术语可保留英文（如 ORM、JWT、SQLModel）
3. 注释粒度：尽量逐行；若某些行逐行注释会极度冗余（例如连续导入/样板代码），可以合并为“按小段解释”，但必须覆盖到所有关键行
4. 不引入新依赖、不重构、不重排代码结构（除非格式化工具强制）
5. 遵循仓库已有风格（例如已有大量行尾注释，则优先行尾注释；若已有块注释风格，则保持一致）
6. 处理类型检查/格式化：
   - 若仓库使用 ruff/black 等格式化，允许格式化工具对换行做最小调整
   - 任何新增注释不得导致 lint/typecheck 失败

## 执行步骤（给模型的操作流程）

1. 读取用户指定文件（或用户当前打开文件）并理解其职责
2. 先识别该文件的注释风格（行尾注释 / 块注释 / docstring）
3. 逐行补齐注释：
   - import：解释引入目的（类型、模块职责），必要时说明为何用 cast/type: ignore
   - 常量：来源、单位、默认值含义
   - 模型/字段：业务含义、约束（unique/index/max_length/min_length）、是否必填、默认值来源
   - 路由：路径、方法、依赖注入、权限、返回模型、异常分支
   - 数据库操作：查询条件、事务边界、级联删除、潜在一致性问题
4. 检查注释是否与代码一致（避免“注释说 A，代码做 B”）
5. 如项目存在统一检查脚本，给出建议的命令以验证（由用户或自动流程执行）

## 使用示例（用户怎么说）

- “对我当前打开的文件逐行加中文详细注释，只加注释不要改逻辑。”
- “请用 line-commenter 处理 /root/omniapi/backend/app/models.py，把每行都注释清楚。”
- “我接下来改动的代码都按逐行注释风格补齐。”
