# SKILL：错误处理与返回标准（Trae）

【定位】这是 Trae Skill，用于统一后端异常处理与对外返回，保证调用方可预测、可排查，同时避免泄露敏感信息。

## 何时触发

- 新增/修改 FastAPI 路由、依赖、服务层逻辑
- 处理第三方请求失败、解析失败、鉴权失败、资源不存在等错误分支

## 强制规则（必须遵守）

### 1) 错误分类（状态码语义一致）

- 参数问题（客户端可修复）：400/422（指出哪个参数不合法、期望格式是什么）
- 鉴权问题：401/403（不暴露“用户是否存在”等枚举信息）
- 资源不存在：404（资源类型 + 标识，不含敏感信息）
- 上游服务异常：502/503/504（提示上游异常/超时/稍后重试；不附 token/原始响应全文）
- 服务器内部错误：500（通用提示；不回传堆栈）

### 2) HTTPException 使用规范

- 在路由/依赖中优先使用 `HTTPException(status_code=..., detail=...)`。
- `detail` 面向调用方：可读、可操作；不要直接塞入 Python Exception 原始信息（尤其包含内部路径/堆栈）。

### 3) 服务层异常处理

- 服务层捕获异常时：
  - 对外 message：稳定、可操作，不包含内部堆栈
  - 对内记录：只记录排查必要信息，不记录 token/密码/连接串
- 若必须做“上游错误透传”，必须过滤敏感字段并做长度限制，并在注释中说明原因。

### 4) 返回结构一致性

- 同一接口成功/失败响应结构尽量一致：
  - `message`：始终存在（成功/失败都给）
  - `data`：成功为对象；失败为 `None`（或省略，但要一致）
- 不要在失败时突然改成完全不同的 JSON 结构。

### 5) 注释要求（错误分支必须解释）

新增/修改错误分支时，必须在关键分支处补充中文注释，说明：
- 为什么判定为该错误（触发条件）
- 对外返回什么（message/detail）
- 是否可重试/是否需要调用方修复输入
