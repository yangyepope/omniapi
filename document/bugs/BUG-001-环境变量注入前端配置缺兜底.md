# BUG-001 环境变量注入前端配置缺兜底

- **编号**: BUG-001
- **建档日期**: 2026-07-06
- **关联 FIX**: [FIX-011](../changelog/FIX-011-前端API基地址undefined导致登录404.md)(记录修复过程;本档案只沉淀防线,不复述过程)
- **关联规则**: `.claude/rules/bug-复盘-frontend.md` F-003

## 根因(架构级)

`import.meta.env.VITE_*` 变量在构建/启动环境未注入时值为 `undefined`,而项目契约(`compose.yml:224`)规定"留空 = 相对路径走代理"。**契约只写在注释里,没有落到代码的唯一入口**:`OpenAPI.BASE`、`security/api.ts` 等多处各自读取 `VITE_API_URL`,有的兜底有的不兜底,形成双轨——环境变量缺失时,兜了底的模块正常、没兜底的模块把 `undefined` 拼进 URL,产生 `/undefined/api/...` 这类只有运行期才暴露的 404。

一类问题的共性:**凡把环境变量直接赋给运行时配置(API 基地址、WS 地址、上报端点),缺失时的语义必须在赋值处显式表达**,不能依赖"部署时一定会注入"。

## 复发防线(tripwire,至少一条可执行)

```bash
# 检测"无兜底的 VITE_API_URL 引用":输出为空 = 通过
grep -rn 'import\.meta\.env\.VITE_API_URL' frontend/src --include='*.ts' --include='*.tsx' \
  | grep -v '||' \
  && echo "⚠ 存在无兜底的 VITE_API_URL 引用,缺失时会拼出 /undefined/..." \
  || echo "✅ 通过"
```

补充不变量:新增 `VITE_*` 变量时,声明(`src/vite-env.d.ts`)、读取处兜底、`compose.yml` 构建参数三处必须同步。
