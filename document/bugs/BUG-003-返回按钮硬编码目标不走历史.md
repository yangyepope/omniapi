# BUG-003 返回按钮硬编码目标、不走历史

- **编号**: BUG-003
- **建档日期**: 2026-07-08
- **关联 FIX**: [FIX-013](../changelog/FIX-013-返回按钮硬编码跳大屏.md)(记录修复过程;本档案只沉淀防线,不复述过程)
- **关联规则**: `.claude/rules/bug-复盘-frontend.md` F-006;`.claude/rules/05-前端一致性规范.md` §六 数据流/导航

## 根因(架构级)

**"返回 / 上一步"这类导航按钮把目标 route 写死,而不是消费浏览器/路由历史。**

一个可从**多个入口**下钻进入的详情页(finding 详情能从大屏、findings 列表、服务详情进入;
服务详情能从大屏、finding 详情进入),它的"返回"语义天然是"回到进入本页的那一步"——
这是运行期才知道的、由导航历史决定的动态目标。用 `<Link to="/固定路由">` 把它固化成一个静态目标,
等于假设"所有人都从同一个地方来",对除该入口外的所有入口都是错的。这不是"某行写错",
而是**用静态链接表达了本该由历史驱动的动态返回**的设计错位。

## 复发防线(tripwire,至少一条可执行)

安全区页面里,凡是带"返回/上一步"文案又配左箭头图标的入口,不得再用 `<Link to=...>` 写死目标;
应走 `useCanGoBack()` + `router.history.back()`(无历史再兜底 navigate)。下面的 grep 抓"返回类文案挂在 Link 上":

```bash
# 输出为空 = 未复发;有输出 = 有"返回"文案的 Link,核对是否该改成 history.back()
grep -rnE '<Link[^>]*>' frontend/src/routes/_layout/security frontend/src/components/security \
  -A2 | grep -E '返回|上一步|后退' \
  && echo "❌ 发现写死目标的返回链接,应走 router.history.back()" || echo "✅ 通过"
```
