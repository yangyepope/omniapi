> 每个功能一份,长期维护。功能优化 / 修改时**更新本文档**并在文末《修改记录》追加一行,不新建文档。

## 需求背景

区分并展示每次扫描任务的触发来源:webhook 自动(push / merge_request)还是控制台手动;并给出触发人、分支+MR、触发时间。此前 `scan_runs` 完全不记录这些,列表/详情无从区分。

## 数据结构 · 数据库设计

数据落在 **gitlab-scanner** 侧(平台不落库):`scan_runs` 新增 5 可空列
`trigger_type` / `trigger_actor` / `trigger_ref` / `trigger_mr_iid` / `triggered_at`。
- 迁移:`gitlab-scanner/backend/app/db/migrations/versions/d7e2f9a1c4b8_add_scan_run_trigger_meta.py`
- 模型:`gitlab-scanner/backend/app/db/models.py` `ScanRunRow`
- 落库时机:`app/services/scan_resume.py` `open_or_resume_run(event=...)` **仅开新行**写入,resume 不覆盖
- 手动/自动判定:`app/models/event.py` `ChangeEvent.manual`(admin 路由置 True)→ `trigger_type='manual' if manual else event_type`

前端类型(允许手写的透传类型):`frontend/src/security/api.ts` `ScanRun` 补 5 个可选字段。

## 配置项

无。

## 接口列表

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/security/services/{name}/scan-runs` | 单服务扫描历史(透传,含触发字段) |
| GET | `/security/services/{name}/scan-runs/{id}` | 单次扫描详情(透传,含触发字段) |
| GET | `/security/scan-runs` | 全服务聚合任务总览(透传,含触发字段) |

平台代理均为纯透传(`ScannerClient.list_scan_runs`/`get_scan_run` → `r.json()`),无 response schema 裁剪。

## 与其他模块的交互

- 依赖 gitlab-scanner 提供触发字段。**失败降级**:若下游 scanner 尚未 rebuild 落迁移,响应无这些字段 → 前端渲染「未知 / —」,不报错、不阻断列表。
- MR 链接由前端用 `useServiceList` 已缓存的服务 `repo_url` 客户端拼接(`{repo_url 去 .git}/-/merge_requests/{iid}`),无 repo_url 降级纯文本,不新增后端列。

## 影响范围

- gitlab-scanner:`scan_runs` 表 + `open_or_resume_run` 签名(新增可选 `event`,向后兼容)+ `ScanRunItem`/`ScanRunDetail` 响应。
- 平台后端:无改动。
- 前端:`security/api.ts`、`components/security/{theme,badges}`、`routes/_layout/security/tasks.tsx`、`security/ScanRunDetailPanel.tsx`。
