# 扫描引擎页

- **创建日期**: 2026-07-11
- **状态**: 已上线
- **关联变更**: [FEAT-015](../changelog/FEAT-015-扫描引擎页.md)(消费 gitlab-scanner FEAT-028)

> 平台侧只做**代理 + 展示 + 配置编辑**;引擎目录与运行都在下游 gitlab-scanner。

## 需求背景

「全局配置 → 扫描引擎」页:展示 scanner 的插件式扫描引擎目录、每引擎参数配置、健康与
成本观测。引擎全局(不随项目)。是"代码扫描"能力对用户可见的入口——看清装了哪些引擎、
是否生效、参数几何、近期成本。

## 数据结构 · 数据库设计

无平台侧 DB 变更。引擎目录来自 scanner `GET /engines`(声明式目录 + live 健康探测)。

## 配置项

无平台侧新增配置。引擎参数走已有 `/security/config`(engines/ai 分类)。

## 接口列表

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/security/engines` | 引擎目录(name/display/kind/enabled/binary_present/optional/config_keys) |
| GET/PUT | `/security/config` | 每引擎参数(按 `config_keys` 归拢,复用) |
| DELETE | `/security/config/{key}` | 行级重置为 env/默认 |
| GET | `/security/cost-stats` | 按 engine_name 聚合的近 N 天运行/成本 |

## 前端

- `security/api.ts`:`EngineItem` + `engines()`。
- `security/hooks.ts`:`useEngines`、`useEngineCostStats`(全局,不注入当前项目)。
- `security/configEditor.tsx`:配置控件共享模块(`editorKind`/`parseValue`/`displayValue`/
  `ValueEditor`),`ConfigPage` 与 `EnginesPage` 共用(单一真相源)。
- `security/EnginesPage.tsx`:目录表 + 行内配置抽屉(dirty/保存/重置,AI 三键标注可项目覆盖)。
- `routes/_layout/security/engines.tsx` + `SettingsHubTabs`(Tab)+ `Sidebar`(区高亮)。

## 约束(务必保持)

1. 引擎列表来自 `GET /engines`,**禁止硬编码**——后端加引擎自动多一条。
2. 不做「新增引擎」按钮(那是后端代码 + 装二进制)。
3. 引擎全局,放「全局配置」下,不进项目详情页。
4. `enabled=false`/`binary_present=false` 的引擎照常显示并标注,不隐藏。

## 影响范围

- `backend/app/services/scanner_client.py`、`backend/app/api/routes/security.py`
- `frontend/src/security/{api.ts,hooks.ts,configEditor.tsx,ConfigPage.tsx,EnginesPage.tsx,SettingsHubTabs.tsx}`
