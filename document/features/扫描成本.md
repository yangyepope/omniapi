## 需求背景

「扫描成本」页展示每次扫描的 AI token 用量与 wall-clock 耗时。原本只有「全局 + 按引擎」两个维度,用户需要再下钻两级:**②按单个服务** 与 **③按单次扫描(显示具体那次什么时间)**。

数据在外部 gitlab-scanner 服务(`scan_engine_runs` 表),平台 backend 以 `/api/v1/security/*` 代理其 `/api/admin/*`,前端只对接 backend 代理,从不直连 scanner。

> **为什么一开始没数据**:`scan_engine_runs` 为空——4 次真正跑完的扫描早于成本记录功能上线(未采集 token),之后的扫描均未完成。写入链路本身正确,扫描正常完成后成本会自动落库;**历史扫描无法回填**。

## 数据结构 · 数据库设计

无平台侧落库。数据源为 gitlab-scanner 的 `scan_engine_runs`(一行一个 `(scan_run, engine)`:`elapsed_seconds / findings_count / input_tokens? / output_tokens? / model? / status / finished_at`,唯一约束 `uq_scan_engine_run_unique`)。写入见 scanner `app/services/scan_resume.py::record_engine_run`(AI 引擎 / risk_classify / finding_review 三处调用)。

前端类型(`frontend/src/security/api.ts`):
- `CostStats`:全局汇总 + `by_engine: EngineCost[]` + `by_service: ServiceCost[]`。
- `ServiceCost`:`service / *_tokens / elapsed_seconds / runs(去重扫描次数) / findings / last_run_at`。
- `RunCost`:一次扫描的汇总 + `by_engine: EngineRunDetail[]`;`run_id / service / sha / started_at / finished_at / status`。

## 配置项

无新增。沿用 `SCANNER_BASE_URL`、`SCANNER_ADMIN_TOKEN`(`backend/app/core/config.py` + 根 `.env`)。

## 接口列表

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/security/cost-stats?service=&days=` | 既有。全局汇总 + 按引擎;**本次响应新增 `by_service`** |
| GET | `/api/v1/security/cost-runs?service=&days=&limit=` | **新增**。最近 limit 次有成本记录的扫描,每条含逐引擎明细,按 started_at 倒序 |

代理链:backend `security.py` → `ScannerClient.cost_stats/cost_runs` → scanner `/api/admin/cost-stats`(增 `by_service`)、`/api/admin/cost-runs`(新增)。前端消费:`SecurityApi.costStats/costRuns`、`useCostStats/useCostRuns`。

## 与其他模块的交互

- **依赖**:外部 gitlab-scanner(经 backend `ScannerClient` 代理)。
- **失败降级行为**:scanner 不可达/鉴权错 → `_call_scanner` 映射 502/503/504,前端页面显示「无法加载成本数据 / 无法加载扫描明细」错误态;窗口内无数据 → 各分区显示空态(EmptyBlock)。
- **联动**:按服务表点击某行 → 设置服务筛选,`cost-stats` 与 `cost-runs` 两个 query 的 key 变化自动重取(再点当前行或筛选器选「全部服务」清除)。
