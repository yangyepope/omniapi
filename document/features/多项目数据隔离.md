# 多项目(租户)+ 数据隔离

- **创建日期**: 2026-07-09
- **状态**: 已上线
- **关联变更**: [FEAT-011](../changelog/FEAT-011-多项目租户数据隔离前端对接.md)

> 依赖 gitlab-scanner 后台 FEAT-024/025。本文档记录控制台侧对接;隔离能力真相源在 scanner。

## 需求背景

系统支持多项目/多租户:`Project`(租户)= 一个团队的整片服务;`Service`(git 仓库)属且仅属一个项目(跨项目重复 repo_url → 409,ADR-0019);findings/接口/知识按项目隔离,项目间不互通、不互相分析。存量数据都在 `default` 项目下。控制台需加「当前项目」全局选择器 + 项目/服务管理页,并让数据视图按当前项目过滤。

## 数据结构 · 数据库设计

平台侧无新增表(纯代理 + 前端状态)。真相源 scanner 侧 `ProjectRow` / `ServiceRecordRow`,迁移在 gitlab-scanner 仓库(FEAT-024/025),本仓不维护。前端当前项目状态存 localStorage(`security.current_project`,默认 `default`)。

## 配置项

无新增。沿用平台既有 `SCANNER_BASE_URL` / `SCANNER_ADMIN_TOKEN`(见 `backend/app/core/config.py`)。

## 接口列表

平台代理(`/api/v1/security/*`,JWT;转发到 scanner `/api/admin/*` + X-Admin-Token):

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/security/projects` | 列项目 `{total, items[]}` |
| POST | `/security/projects` | 建项目;重名 key → 409;created_by 缺省注入当前用户 |
| PUT | `/security/projects/{key}` | 改 name / enabled |
| DELETE | `/security/projects/{key}` | 删项目(连带服务定义);default → 400 |
| GET | `/security/projects/{key}/services` | 列该项目服务 |
| POST | `/security/projects/{key}/services` | 加服务;项目不存在 404;重名 409;repo 跨项目 409 |
| PUT | `/security/projects/{key}/services/{name}` | 部分更新服务 |
| DELETE | `/security/projects/{key}/services/{name}` | 删服务 |
| GET | `/security/findings?project=` | findings 列表按项目过滤(原生) |
| GET | `/security/services/{name}/ai-context?project=` | AI 上下文预览按项目定位(原生) |

## 与其他模块的交互

- 前端所有安全区取数经 `security/api.ts`(裸 axios)→ 平台 `security.py` 代理 → `ScannerClient` → scanner。
- **失败降级**:代理层 `_call_scanner` 把 scanner 的 400/404/409/422 原样透传 detail;401/403(平台↔scanner 凭据问题)转 502;网络错误转 504。前端 `scannerErrorDetail` 提取 detail 走 sonner toast。
- **服务视图隔离依赖 scanner `/projects/{key}/services` 成员清单**:该接口不可用时 `useServiceList` 会因 `Promise.all` 失败而报错(四态里走 error 态),不会静默显示全部——符合隔离语义。

## 影响范围

- 后端:`app/services/scanner_client.py`、`app/api/routes/security.py`。
- 前端:`security/api.ts`、`security/hooks.ts`(`useServiceList` 过滤行为变更,影响扫描管理树 / 大屏服务健康 / 知识页服务下拉)、`main.tsx`、`components/layout/Header.tsx`(加 `rightSlot`)、`routes/_layout.tsx`;新增 `CurrentProjectProvider`、`ProjectSelector`、`ProjectsPage`、`ProjectServicesPage`、`ProjectCreateDialog`、`ServiceFormDialog`、`formKit`、路由 `projects.tsx` / `projects.$key.tsx`。

## 当前边界

**聚合端点已全部项目化(2026-07-10 补齐,原 M3 缺口已消除)**:`/stats`、`/stats/trend`、`/categories`、`/verifier-stats`、`/finding-review-stats`、`/cost-stats`、`/cost-runs`、`/services` 均已加 `project=` 过滤;`/scan-runs` 总览经 `list_services(project=)` fan-out 隔离。大屏/成本/任务全链路按当前项目隔离。

**仍全局(按设计,不隔离)**:`/config`、`/ai/categories`、`/ai/rules`、`/ai/skills`、`/ai/custom-rules`——这些是扫描配置与规则库(`app_config`/`ai_hunt_categories`/`ai_custom_rules` 无 project 列),属公共资产,不随项目切换。

**部署注意**:scanner 端点改动在 `gitlab-scanner/backend/app/api/routes/admin.py`,scanner 镜像未挂源码,需**重建镜像**(`docker compose build scanner && docker compose up -d scanner`)才持久生效(验证时用 `docker cp`+`restart` 热替换过)。

## 验证方式

见 FEAT-011《验证方式》:前端 tsc/Biome/路由树/Vite 转译均通过;后端 curl 全流程(建/加/409/400/清理/project 过滤)通过;聚合隔离 curl 验证:`stats?project=aigs-middleground`→1040/11、`?project=ghost`→0/0、`services?project=` 精确、`cost-stats?project=` 正常。
