# 前端实现:系统画像(系统级视图)+ 渗透视角 —— 服务详情页 Tab

> 交接提示词。后端(gitlab-scanner FEAT-029 + 平台代理 FEAT-014)已上线,前端照此实现即可对上。

## 背景

系统画像是对**被扫描目标服务**的一份系统级视图,把散落的四维 +（渗透)一维聚成一处、可读,给安全测试/渗透打底:**系统框架 / 技术流程 / 暴露面 / 风险点 / 渗透视角** + AI 叙述。它是 **per-service** 的,挂在**服务详情页的一个 Tab**(不是顶层菜单)。画像在扫描流水线末尾自动生成,也可手动「重新生成」。

所有请求走平台 JWT 代理:`Authorization: Bearer <token>`,基址 `/api/v1/security`。按**当前项目**隔离(和其他 security 页一致,从 CurrentProject 注入 `project`)。

---

## 1. 取画像 —— `GET /api/v1/security/services/{name}/system-profile`

Query:`sha?`(省略=最新一份)、`project?`(当前项目)。

**无画像 → 404**(服务从未扫描过 / 画像未生成)。前端把 404 当作**"尚未生成"**处理:显示"请先扫描",**不报错、不重试**(react-query `retry:false`)。

### 字段语义 / UI 建议

| 维 | 字段 | 含义 / 渲染 |
|---|---|---|
| **系统框架** | `framework.framework` + `framework_version` | 框架 + 版本,主标 |
| | `primary_language` / `build_tool` / `languages[]` | 主语言 / 构建工具 / 语言分布 chip(`language·file_count`) |
| | `key_dependencies[]` | `{group,name,version,key}`;**只渲染 `key===true` 的**做「关键依赖」chip(蓝色,`name:version`) |
| | `layers[]` | `{name, packages[], file_count}` 架构分层:层名 + 代表包名 + 文件数 |
| **暴露面** | `total_endpoints` | 大数字 |
| | `by_risk` | `{P0,P1,P2,unclassified}` → 风险徽章 + 数字(复用 `RiskBadge`) |
| | `by_method` | 方法分布(复用 `MethodBadge`) |
| | `sensitive_interface_ids[]` / `admin_interface_ids[]` | **只给 id**,展示数量 + 提示"见接口 Tab 下钻";可点跳 `/security/interfaces/{id}` |
| | `feign_count` / `outbound_count` | Feign / 出站计数 |
| **技术流程** | `outbound[]` | `{host,path,method,resolution}` 出站调用 chip |
| | `feign[]` | `{interface_fqn,target_service,base_url}` Feign 契约 chip(优先显示 `target_service`) |
| | `cross_service[]` | `{outbound_call_id,target_interface_id}` 跨服务边(计数即可) |
| | `key_flows[]` | `{name,steps[],narrative}` AI 关键请求流:名 + 步骤(`step → step`)+ 一句叙述 |
| **风险点** | `open_total` / `open_by_severity` | 大数字 + 按严重度徽章(复用 `SeverityBadge`,顺序 CRITICAL→INFO)|
| | `top_finding_ids[]` | **只给 id**,渲染成链 `/security/findings/{id}`(#id chip) |
| | `themes[]` | CWE 主题 chip;`group_count` = 互证组数 |
| **渗透视角** | `entry_points[]` | `{interface_id,method,path,risk,sensitivity}` P0/P1 入口点,整行可点跳 `/security/interfaces/{interface_id}`(带 RiskBadge+MethodBadge) |
| | `injection_candidates[]` | `{cwe,label,finding_ids[],count}` 注入点候选:红色标 `label·cwe` + 逐 finding_id 链到 `/security/findings/{id}` |
| | `trust_boundaries[]` | `{name,kind}`(kind=`http`\|`feign`)信任边界 chip |
| | `not_derivable_from_code[]` | 底部灰字提示"代码侧无法判定(需主机/部署侧):…" |
| **叙述/元信息** | `narrative` | markdown,`whitespace-pre-wrap` 或轻量 md 渲染 |
| | `sha` / `generated_at` / `model` | 头部一行:sha 前 12 位 + 生成时间 + 模型 |
| | `generator_version` | 内部版本,不展示或作 title |

## 2. 历史 —— `GET /api/v1/security/services/{name}/system-profile/history?project=`

返回:`{ "items": [{ "sha": "...", "generator_version": "v2+...", "generated_at": "..." }] }`(新→旧)。用于「查看历史 sha 的画像」下拉(可选,先做也行不做也行;做的话选中后带 `?sha=` 重取第 1 个接口)。

---

## 3. 重新生成 —— `POST /api/v1/security/services/{name}/system-profile/regenerate?project=`

- 免源码,刷新最新画像的**聚合 + AI 叙述**(同一 sha,框架事实复用)。返回体同接口 1。
- **无画像时 404**("先扫描一次")。成功后 toast + `invalidateQueries(["security","system-profile",name])`。
- mutation 内联在面板里(仿现有页做法),按钮带 loading。

## 约束(务必遵守)

1. **不硬编码任何清单**——五维全部来自接口。后端加维/加字段前端不该崩(未知字段忽略,数组缺省 `[]`)。
2. **引用不复制**:暴露面/风险/渗透里的接口和 finding **只给 id + 少量标签**,明细一律**下钻**到已有页——接口 `/security/interfaces/{id}`、finding `/security/findings/{id}`。前端不要再拉一份接口/finding 全量塞进画像。
3. **per-service**:挂服务详情页 Tab,**不进顶层侧边栏**。
4. **404 = 尚未生成**:显示"请先对该服务完成一次扫描",不报错、不重试(`retry:false`)。
5. **按当前项目隔离**:`project` 从 CurrentProject 注入(和其他 security 页一致)。
6. **渗透视角的诚实边界**:`not_derivable_from_code` 一定要展示——明确告诉用户"外部可达性 / 运行时鉴权是否真挂"这些**代码侧判不了、需主机侧实测**,不要让 UI 显得"全都知道"。
7. **扫描进度条**补一个 `system_profile` 阶段(label「系统画像」),排在「AI 复核」之后(改 `components/security/theme.ts` 的 `STAGE_ORDER` + `STAGE_META`)。
