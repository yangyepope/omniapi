# SecurityPlatform 十万级高并发与异构协程基座调优报告 (2026-04-06)

## 1. 核心挑战背景
在 SecurityPlatform 核心重写过程中，系统面临两个极端并发场景：
*   **流量采集 (Collect)**：需承接来自上游 Nginx Mirror 的瞬时十万级（100,000+）请求冲刷。
*   **变体重放 (Replay)**：需在 10s 内发起 1000+ 并发流量攻击，对出站 I/O 和数据库原子计数的稳定性要求极高。

## 2. 架构调优与决策
我们通过 **“异构并发模型”** 物理隔离了 API 层与任务层，解决了 `LoopExit` 错误。

### 2.1 异构并发隔离 (Heterogeneous Concurrency)
*   **API 层 (FastAPI Layer)**：保持 **uvloop (Asyncio)** 原生动力，杜绝全局 Gevent 补丁，确保主服务响应稳定。
*   **Worker 层 (Celery Layer)**：精准激活 **Gevent 协程分身**。通过 `CELERY_WORKER_TYPE=gevent` 环境变量，仅让 Worker 进程被补丁，实现百万级 I/O 并发承载。

### 2.2 链路三级通血调优
| 维度 | 操作 | 核心目的 |
| :--- | :--- | :--- |
| **内核/编排** | `ulimits: 65536` & `--backlog 2048` | 解锁文件句柄限制，撑开 TCP 积压队列，避免丢包。 |
| **API 调度** | `AnyIO Thread Pool (40 -> 200)` | 解决同步接口在并发下的线程饥饿，确保响应零排队。 |
| **DB 驱动** | `Pool (100+100)` & `Recycle (3600s)` | 支撑 200 个真实物理连接，防止长周期连接被 Postgres 主动切断。 |
