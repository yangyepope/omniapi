# 20260405 同步重放历史 UI 实施方案

本项目旨在通过 Stitch MCP 协议同步 Figma 原型 `553729816665366717` 中的“重放历史 - 记录列表 (Replay History)”片段，并将其集成到当前项目的流量详情“测试重放历史”页签中。

## 核心设计目标

> [!IMPORTANT]
> 将现有的简单垂直时间轴替换为功能更全的“数据面板 + 过滤栏 + 记录表格”复合设计，显著提升审计效率。

## 拟定改动内容

### 前端组件优化

#### [修改] [HistoryTimeline.tsx](file:///root/omniapi/frontend/src/routes/_layout/services/$serviceId/$endpointId/$trafficId/-components/HistoryTimeline.tsx)
-   **统计区 (Bento Dashboard)**:
    -   使用 `Grid` 布局渲染状态码分布、响应耗时趋势、异常归类。
    -   逻辑实现：基于传入的 `history` 数组动态计算。
-   **筛选区 (Filter Bar)**:
    -   增加针对 Host、状态码、耗时（ms）和关键字的输入控件。
    -   逻辑实现：前端本地 Filter（或配合后续后端分页支持）。
-   **数据表格 (Record Table)**:
    -   使用现代化的 `Table` 结构。
    -   列包含：执行时间、Host、状态码、耗时、变体来源、操作（详情/重放/存为新变体）。
-   **视觉对齐**:
    -   统一使用项目的 HSL 变量（如 `primary-fixed`）。
    -   保持 `rounded-[2.5rem]` 的圆角规范。
    -   图标替换为 `lucide-react` 系列。

## 待确认问题

-   **数据规模**: 当前 `get_history` API 是否支持分页？若不支持，统计区将仅显示当前加载的几十条数据。
-   **视觉基调**: 是否需要在深色模式下进行特殊适配（Stitch 源码中包含 dark-mode 处理）？

## 验证计划

-   **功能验证**: 历史页签切换后，统计仪表盘是否能根据流量历史正确汇总数据。
-   **交互验证**: 过滤功能是否能准确过滤出预期的历史记录。
-   **视觉审计**: 录制视频确认平滑切换效果及 24 小时制显示。
