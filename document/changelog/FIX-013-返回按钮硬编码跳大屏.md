# FIX-013 返回按钮硬编码跳大屏而非回上一步

- **编号**: FIX-013
- **日期**: 2026-07-08
- **状态**: 已完成
- **类型**: Bug 修复
- **关联 PR·Issue**: 无
- **关联 BUG**: [BUG-003](../bugs/BUG-003-返回按钮硬编码目标不走历史.md)(本文件记录一次修复过程,防线沉淀见 BUG-003)

## 需求背景

用户在 finding 详情页(`/security/findings/609`)反馈:左上角"返回大屏"按钮点了直接甩到安全大屏,
而不是回到进入本页的上一步(如 findings 列表 / 服务详情)。从任意入口下钻进来都被强制送去大屏,交互割裂。

## 技术实现

**根因**:返回按钮用 `<Link to="/security-dashboard">` 把目标**写死**成大屏,与"从哪进来"无关。
finding 详情本可从大屏、findings 列表、服务详情等多个入口下钻,单一硬编码目标必然对多数入口是错的。
同一反模式在**服务详情页**(`services/$name.tsx`)同样存在——它还能从 finding 详情的"服务详情 →"进入,
`finding → 服务详情 → 返回大屏`会直接跳走而非回到 finding。两处同根因,一并正面修复,不留双轨。

**改动定位**:
- [frontend/src/routes/_layout/security/findings/$id.tsx](../../frontend/src/routes/_layout/security/findings/$id.tsx) — `<Link>` 改 `<button onClick={goBack}>`,文案"返回大屏"→"返回"。
- [frontend/src/routes/_layout/security/services/$name.tsx](../../frontend/src/routes/_layout/security/services/$name.tsx) — 同上。
- 两处都用 TanStack Router 的 `useCanGoBack()` + `router.history.back()`:有历史回上一步(从哪进来回哪去);
  无历史(直接粘贴 URL 打开、新标签页)才 `router.navigate({ to: "/security-dashboard" })` 兜底回大屏。
- `Link` 在两文件内仍被其他链接使用,无孤儿 import。
