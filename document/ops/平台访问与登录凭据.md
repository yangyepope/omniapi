## 操作步骤

### 一、项目启动

```bash
# 1. 启动后端全栈容器(backend/db/redis/proxy/celery/aisec/temporal 等)
cd /home/dreamer/security-platform
docker compose up -d

# 2. 启动前端开发服务(当前部署方式,监听 5173,支持热更新)
bun run dev

# 3. 确认容器全部在跑(backend/db 应为 Up (healthy))
docker compose ps
```

> 前端也可用容器方式跑(`docker compose up -d frontend`,同样映射 5173),但当前环境默认前端容器不启动、走 Vite 开发服务。两种方式二选一,勿同时占用 5173。

### 二、后端代码更新

后端源码已挂载进容器(`./backend:/app/backend`)且 uvicorn 带 `--reload`,**改 Python 代码保存后 API 自动热重载,无需任何命令**。以下场景才需要操作:

```bash
# 场景 1:改了 Celery 任务代码(worker 不会热重载,必须手动重启)
docker compose restart celery-worker-default celery-worker-replay

# 场景 2:改了依赖(pyproject.toml / uv.lock)或 backend/Dockerfile,需重建镜像
docker compose build backend
docker compose up -d backend celery-worker-default celery-worker-replay

# 场景 3:改了 compose 文件中 backend 相关配置(环境变量/端口/命令)
docker compose up -d backend

# 场景 4:有新的数据库迁移(alembic)
docker compose exec backend alembic upgrade head
```

### 三、前端代码更新

```bash
# 开发模式(当前方式):Vite 热更新,改代码保存即生效,无需命令
# 若改了依赖(package.json),先装依赖再重启 dev 服务
cd /home/dreamer/security-platform/frontend && bun install
cd /home/dreamer/security-platform && bun run dev

# 若后端接口(OpenAPI)有变更,重新生成前端 API 客户端
cd /home/dreamer/security-platform/frontend && bun run generate-client

# 容器方式部署时:重建前端镜像并重启
cd /home/dreamer/security-platform
docker compose build frontend
docker compose up -d frontend
```

## 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 前端 5173 打不开 | Vite 开发服务未启动 | 根目录执行 `bun run dev` |
| 局域网访问报 HTTP 502 | 访问者电脑的代理软件(Clash 等)拦截了内网地址 | 代理软件勾选"绕过局域网地址"或 bypass 列表加 `192.168.0.0/16` |
| 登录请求 404 且 URL 含 `/undefined/api/...` | 前端读取 `VITE_API_URL` 处缺空串兜底 | 见 [BUG-001](../bugs/BUG-001-环境变量注入前端配置缺兜底.md),跑其 tripwire 定位无兜底引用 |
| 登录返回 401 | `.env` 凭据被改动或数据库未初始化 | 核对 `.env` 中 `FIRST_SUPERUSER*`,查看 `docker compose logs backend` |
| 8004 无响应 | backend 容器未启动 / 不健康 | `docker compose ps` 查看状态,`docker compose logs -f backend` 排错 |
| E2E 测试 401/403 | 登录态过期 | 运行 `npx playwright test tests/auth.setup.ts` 重新持久化登录态 |
