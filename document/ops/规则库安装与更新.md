# 从 claude-rules 安装 / 更新规则

> 通用规则集中维护在独立仓库 `~/claude-rules`,本项目按需安装。
> 项目特化规则(02/03/05/07/08/09、bug 清单积累内容)留在本地,安装不覆盖。

## 仓库位置

- 通用规则库:`/home/dreamer/claude-rules`(独立 git 仓库,与本项目平级)
- 结构:`rules/{common,backend,frontend,bug-lessons}` + `install.sh` + `README.md`

## 首次安装(在本项目根目录执行)

```bash
# common 总是装;按需追加 backend / frontend / bug
~/claude-rules/install.sh backend frontend bug
```

规则文件平铺进 `.claude/rules/`(paths frontmatter 要求文件直接在该目录下才能按需加载)。

## 查看可装规则集

```bash
~/claude-rules/install.sh --list
```

| 规则集 | 内容 | 加载范围 |
|---|---|---|
| common(总是装) | 规则组织母版 + 协作准则 | 全局 |
| backend | FastAPI 最佳实践 + DB 并发安全 | `backend/**`、`aisec/**` |
| frontend | 前端一致性规范 + ts 全栈母版 | `frontend/**` |
| bug | 前后端踩坑清单 | 分端 |

## 更新已装规则

规则是复制式安装,更新 = 拉最新后重装:

```bash
cd ~/claude-rules && git pull          # 若已配远程
cd /home/dreamer/security-platform
~/claude-rules/install.sh --force backend frontend   # --force 覆盖通用规则
```

- `--force` 只覆盖 common/backend/frontend 的通用规则。
- **bug 踩坑清单例外**:`bug-复盘-*.md` 是"只播种一次"文件,即便 `--force` 也不覆盖,
  保护本项目已积累的坑记录。想换新种子需先手动备份再删除重装。

## 指定其它项目安装

```bash
~/claude-rules/install.sh --target ~/另一个项目 backend bug
```

## 注意

- 安装后检查各规则头部 `paths:` 是否匹配本项目目录布局(本项目后端在 `backend/`、`aisec/`,前端在 `frontend/`)。
- 不要把 `01-协作准则` 类通用规则同时留在本项目 `.claude/rules/` 和全局 `~/.claude/rules/`——会双份注入(见 `.claude/rules/00-规则组织母版.md` 反模式)。本项目该规则由全局 `~/.claude/rules/collaboration-rules.md` 提供,不在本地留副本。
