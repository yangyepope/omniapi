# 前端改动生效(重启/重构建)操作手册

- **适用场景**: 改了 `frontend/` 下的前端源码(组件/类型/样式)后,让改动在浏览器里生效。判断依据:前端是本机 Vite 开发模式跑,还是 compose 的 `frontend` 容器(nginx 静态产物)跑。
- **最后验证日期**: 2026-07-08

## 前置条件

- 先确认前端在哪跑(决定用下面哪种):
  ```bash
  # 有输出 = 本机 Vite 开发模式在跑 → 用「情况 A」
  pgrep -af "vite|bun run dev"
  # 看 frontend 容器是否在这个 compose stack 里 → 有则可用「情况 B」
  docker compose ps | grep frontend
  ```
- **纯前端源码改动不需要重启后端 / scanner / aisec**;仅当改了后端代码或 compose 定义时才动对应容器。

> ⚠️ **情况 A 与情况 B 不能同时开**:两者都占用宿主机 **5173** 端口。若本机 `bun run dev` 正在跑,再执行 `docker compose up -d frontend` 会报
> `failed to bind host port 0.0.0.0:5173/tcp: address already in use`。
> **正在用 `bun run dev` 开发时,根本不需要 build/up 容器**——改动已被 Vite HMR 热更新,硬刷浏览器即可。要切容器,先停 dev server 释放 5173(见故障排查)。

## 操作步骤

### 情况 A:本机 Vite 开发模式(`bun run dev`)

Vite 有 HMR,**不用重启进程**,保存即热更新。只需刷新浏览器:

```bash
# 通常无需任何命令,浏览器刷新即可;若页面没更新再硬刷清缓存:
#   浏览器内按 Ctrl+Shift+R(Mac: Cmd+Shift+R)
# 万一 HMR 卡死,才重启 dev server:
# 在跑 dev 的终端 Ctrl+C 后:
bun run dev
```

预期:终端打印 `hmr update /src/...`,浏览器自动刷新对应模块。

### 情况 B:compose 的 `frontend` 容器(nginx 静态产物)

`VITE_*` 在**构建时**打包进产物,改源码必须重新 build 才生效,单纯 `restart` 无效:

```bash
cd /home/dreamer/security-platform
# 重新构建前端镜像 + 重建容器(只动 frontend,不影响其它服务)
docker compose build frontend && docker compose up -d frontend
```

预期:build 阶段跑完 Vite `bun run build`,`up -d` 输出 `Recreated ... frontend`。

> ⚠️ 只 `docker compose restart frontend` **不会**重新构建,改动不会生效——必须先 `build`。

## 验证

- [ ] 打开安全大屏,确认改动可见(如本次:「开放问题」不再恒为 0,显示真实开放数)
- [ ] 情况 B 额外确认容器已用新镜像:`docker compose ps frontend` 状态 `running`,`docker compose logs --tail=20 frontend` 无报错
- [ ] 硬刷浏览器(Ctrl+Shift+R)排除本地缓存干扰

## 回滚

- 情况 A:`git checkout -- frontend/src/...` 撤销源码改动,dev server 自动热更新回旧版。
- 情况 B:回退代码后重新 `docker compose build frontend && docker compose up -d frontend`;或临时切回上一个前端镜像 tag(若有保留)。

## 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `up -d frontend` 报 `bind host port 0.0.0.0:5173: address already in use` | 本机 `bun run dev`(Vite)已占用 5173,与容器抢同一端口 | 二选一:①继续用 dev → `docker compose rm -sf frontend` 清掉半启动容器,不用跑容器;②改用容器 → 先停 dev(`pgrep -af "bun run dev"` 找 PID 后 `kill`,或在其终端 Ctrl+C)释放 5173,再 `docker compose up -d frontend` |
| 改了代码浏览器没变化 | 浏览器缓存 / Service Worker | Ctrl+Shift+R 硬刷,或开无痕窗口 |
| 情况 B `restart` 后仍是旧界面 | 只 restart 没 rebuild,产物没重编 | 改用 `docker compose build frontend && docker compose up -d frontend` |
| build 报 `VITE_API_URL` 相关 404 | 构建参数未注入 | 见 [FIX-011](../changelog/FIX-011-前端API基地址undefined导致登录404.md),`VITE_API_URL` 留空走相对路径由 nginx 反代 |
| 页面白屏 / route 缺失 | 构建产物不完整 | 看 `docker compose logs frontend`,本地 `bun run build` 复现构建错误 |
