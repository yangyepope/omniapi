# GitLab 扫描配置与成本接入(前后端打通)实施方案

将 gitlab-scanner 新交付的 **运行时配置(FEAT-008)** 与 **成本指标(FEAT-009)** 能力接入
security-platform:后端代理补齐 5 个端点,前端新增「扫描配置」「扫描成本」两页 +
安全大屏「AI 复核质量」面板。至此 scanner 的全部指标与配置均可在平台**展示与修改**。

## 背景与差距分析

security-platform 已有 scanner 代理三件套(`SCANNER_BASE_URL`/`SCANNER_ADMIN_TOKEN` 配置、
`services/scanner_client.py` 转发客户端、`api/routes/security.py` 路由),前端 `src/security/`
模块(大屏/扫描管理/findings/接口下钻)已全链路打通。本次仅补缺口:

| scanner 端点 | 状态(接入前) | 本次动作 |
|---|---|---|
| `GET/PUT/DELETE /api/admin/config`(FEAT-008) | 未代理、无页面 | 代理 + 配置页 |
| `GET /api/admin/cost-stats`(FEAT-009) | 未代理、无页面 | 代理 + 成本页 |
| `GET /api/admin/finding-review-stats`(FEAT-005) | 未代理 | 代理 + 大屏面板 |

## 变更清单

### 1. 后端代理(backend/)

#### [MODIFY] `app/services/scanner_client.py`
- [NEW] `finding_review_stats(service?)` — AI 复核效果统计
- [NEW] `cost_stats(service?, days?)` — 按引擎 token/耗时聚合
- [NEW] `get_config()` / `update_config(updates, updated_by)` / `delete_config(key)` — 运行时配置
  (delete 对应 scanner 204 无 body,方法返回 None)

#### [MODIFY] `app/api/routes/security.py`(依赖 `CurrentUser`,错误经既有 `_call_scanner` 映射)
- [NEW] `GET /security/finding-review-stats?service=`
- [NEW] `GET /security/cost-stats?service=&days=`
- [NEW] `GET /security/config` — 全部可配置项(值/分类/是否覆盖/是否需重启,内部平台明文)
- [NEW] `PUT /security/config` — body `{updates}`;**`updated_by` 强制取 `current_user.email`**
  (审计规则同 triage,不信前端);scanner 侧全量校验,任一非法项 400 整批拒绝
- [NEW] `DELETE /security/config/{key}` — 回落 env/默认,404 透传

配置零新增(复用 `SCANNER_*`);路由聚合点(`api/main.py`)无改动。

### 2. 前端(frontend/src/)

#### [MODIFY] `security/api.ts` / `security/hooks.ts`
- 类型:`ConfigItem/ConfigListResponse/ConfigUpdateResponse`、`EngineCost/CostStats`、`FindingReviewStats`(与 scanner Pydantic 模型逐字段对齐)
- 方法:`getConfig/updateConfig/deleteConfig/costStats/findingReviewStats`
- hooks:`useScannerConfig`(staleTime 30s,不做心跳)、`useCostStats`、`useFindingReviewStats`(30s 心跳)

#### [NEW] `security/ConfigPage.tsx` + 路由壳 `routes/_layout/security/config.tsx` → `/security/config`
- 左侧 5 分类胶囊(接入凭证/扫描引擎/AI·LLM/资源限额/基础设施)+ 右侧配置行 + 搜索
- 按字段类型出控件:bool→开关 pill、int/float→数字框、list→逗号分隔、str→文本框
- 「已覆盖」(cyan)/「需重启」(amber)徽章;行级重置(DELETE)
- 脏值暂存 + 顶部批量保存条,保存 = 单次 PUT;`requires_restart` 非空时 toast 警示

#### [NEW] `security/CostPage.tsx` + 路由壳 `routes/_layout/security/cost.tsx` → `/security/cost`
- 过滤:服务下拉 + 时间窗(7/30/90 天)
- KPI:总 Token(含输入/输出拆分)、输入 Token、总耗时、覆盖引擎数
- 图表:按引擎 Token 堆叠横向柱(输入/输出)+ 按引擎耗时横向柱(recharts,暗色惯例)
- 明细表:engine/runs/findings/输入/输出/总 Token/耗时

#### [MODIFY] `security/SecurityDashboard.tsx`
- Zone 3 扩为三列,新增「AI 复核质量」面板(已复核/误报率/自动关闭 + 按引擎小表)
- 页头新增「成本 →」「配置 →」快捷链接

#### [MODIFY] `components/layout/Sidebar.tsx`
- navItems 新增「扫描成本」(/security/cost)与「扫描配置」(/security/config)两项

### 3. 数据流(打通路径)

```
浏览器(JWT) → security-platform backend /api/v1/security/*
  → ScannerClient(X-Admin-Token) → gitlab-scanner /api/admin/*
  → app_config / scan_engine_runs / finding_verdicts(scanner DB)
```
