# 实施方案 - 修复接口详情页剔重后流量显示为 0 的问题 [2026-04-04 08:32:00]

本方案旨在解决接口详情页中“剔重后流量” (Deduplicated Traffic) 始终显示为 0 的 Bug。根本原因为前端预期的数据字段与后端 `get_module_endpoint_detail` 接口返回的实际字段不匹配。

## 待变更内容

### 后端 (Backend)

#### [修改] [system_modules.py](file:///root/security-platform/backend/app/api/routes/system_modules.py)
- **更新 `ApiEndpointDetailResponse` Schema**: 
  - 新增 `total_traffic_count: in总流量计数)
  - 新增 `dedup_traffic_count: int` (剔重后唯一流量计数)
- **更新 `get_module_endpoint_detail` 业务逻辑**:
  - `dedup_traffic_count`: 计算 `FilteredFlow` 表中对应 `endpoint_id` 的记录总数（即唯一指纹数）。
  - `total_traffic_count`: 计算 `FilteredFlow` 表中所有匹配记录的 `occurrence_count` 之和（即总请求数）。
  - 在 API 响应中返回这两个字段。

### 前端 (Frontend)

#### [生成] [API Client](file:///root/security-platform/frontend/src/client/services.gen.ts)
- 运行 `bun run generate-client`，确保前端类型定义与后端最新的消息结构同步。

#### [修改] [接口详情页 (index.tsx)](file:///root/security-platform/frontend/src/routes/_layout/services/$serviceId/$endpointId/index.tsx)
- 更新数据映射逻辑:
  - `trafficCount` (原始总流量) 映射至后端的 `total_traffic_count`。
  - `uniqueCount` (剔重后流量) 映射至后端的 `dedup_traffic_count`。
