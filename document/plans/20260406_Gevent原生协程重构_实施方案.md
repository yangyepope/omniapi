# 实施方案 - 真实 Gevent 落地与 UV 依赖管理 [2026-04-06]

本方案旨在通过 `gevent` 原生协程池实现真正的 10 万并发重放，并使用 `uv` 规范化依赖管理。

## 用户审核要求 (User Review Required)

> [!CAUTION]
> **架构底层变更**：我们将把重放任务从 `asyncio` 改为 `gevent` 模式。这要求代码风格从 `async/await` 回归到高效的同步风格（由协程劫持），以获得最高的调度性能。

## 拟议变更 (Proposed Changes)

### 1. 依赖管理层 (Dependency)
- **指令**: `uv add gevent`
- **目的**: 补齐生产环境缺失的协程调度库。

### 2. Worker 调度层 (Scheduler)

#### [MODIFY] [worker.py](file:///root/security-platform/backend/app/worker.py)
- **[NEW]** 在文件最开头（第 1 行）插入协程补丁：
  ```python
  import gevent.monkey; gevent.monkey.patch_all()
  ```
- **[REFACTOR]** 移除 `replay_variant_task` 内部的 `asyncio.run`，改为显式的同步调用：
  ```python
  variant = ReplayEngine.execute_variant(variant_id, session)
  ```

### 3. 引擎核心层 (Engine)

#### [MODIFY] [replay.py](file:///root/security-platform/backend/app/services/replay.py)
- **[REFACTOR]** 将所有的 `async def` 改为 `def`。
- **[REFACTOR]** 使用 `httpx.Client` 代替 `httpx.AsyncClient`。
- **[STAY]** 物理保留 SQL 原子计数更新逻辑。

### 4. 连接池单例 (Pooling)

#### [MODIFY] [http_pool.py](file:///root/security-platform/backend/app/core/http_pool.py)
- 增加同步连接池提供者 `get_client()` -> `httpx.Client`。
