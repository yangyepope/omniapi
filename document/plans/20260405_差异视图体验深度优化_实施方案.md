# 差异视图 (DIFF) 深度优化方案

## 问题现状
目前侧滑详情页的“差异对比 (DIFF)”模式在面对非 JSON 响应（如网络连接异常）时表现单薄：
- **统计失真**: 当响应为网络错误字符串时，JSON 解析失败导致显示“0 CHANGES FOUND”，误导用户。
- **视觉盲区**: 缺乏明显的错误状态标识，与普通的成功响应对比在视觉上区分度不够。
- **布局稀疏**: 底部存在大量留白，空间利用率低。

## 提议变更

### 1. 增强型差异引擎 [frontend]
#### [修改] [DiffCodeViewer.tsx](file:///root/security-platform/frontend/src/routes/_layout/services/$serviceId/$endpointId/$trafficId/-components/DiffCodeViewer.tsx)
- **智能诊断逻辑**: 增加对 `CONNECTION_ERROR` 等特殊字符串的识别。
- **状态感知统计**: 
    - 如果检测到网络错误，统计栏显示“网络链路异常 (NETWORK FAILURE)”标识，而非简单的 0 变更。
    - 在这种情况下，自动在统计栏增加一个指向故障详情的快速说明。
- **对比模式切换**: 
    - 正常模式：保持现有的 JSON Path 递归对比。
    - 故障模式：在右侧对比区（Variant Response）应用红色警告背景，并显示“响应未到达”状态。

### 2. UI/UX 视觉重构 [frontend]
- **“智能扫描”条美化**: 增加背景渐变与微动效。
- **代码查看器调整**: 
    - 针对故障内容，使用更符合告警直觉的配色方案（深红炭黑背景）。
    - 优化 `BodyCodeViewer` 在对比模式下的边框处理，消除重叠感。

### 3. 日志记录

## 验证计划
1.  **模拟网络故障**: 触发一个连接不存在 host 的变体，进入 DIFF 模式，确认统计条显示“NETWORK FAILURE”且右侧背景变红。
2.  **正常业务对比**: 触发一个正常 JSON 响应的变体并修改结果，确认 JSON Path 列表显示正常且计数准确。
3.  **响应式核验**: 调整窗口宽度，确认并排视图布局稳定。
