# 核心服务管理模块后端 API 设计与实施方案

根据前端“服务管理”页面的高质量重构需求，我们需要对后端 `SystemModule` 模块进行全面升级。主要涵盖数据模型扩展、CRUD 接口开发、服务发现算法增强及流量统计持久化。

## 用户审核要求

> [!IMPORTANT]
> **API 变更影响**: 本次修改会调整 `SystemModule` 的数据结构。如果当前数据库已有大量数据，建议执行 Alembic 迁移（我将生成对应的迁移逻辑）。
> **服务发现优先级**: 默认行为已改为：1. 全局配置匹配 -> 2. 路径首层提取 -> 3. 自动创建未知服务。需确认业务配置的具体格式（建议为 JSON 数组）。

## 业务逻辑详情：服务状态流转

符合单向流转规范（不可逆）：
1. **Active**: 默认状态，正常接收流量。
2. **Deprecated**: 通过 `PATCH` 或专门接口设置，记录 `deprecated_at`。前端显示为风险/弃用。
3. **Deleted**: 通过 `DELETE` 接口移除，相关接口定义 (Endpoints) 级联删除。
