# 流量管理与重放攻击测试系统 - 需求文档

## 1. 项目概述

### 1.1 系统名称
流量管理与重放攻击测试系统

### 1.2 系统定位
内部工具后台管理系统，用于捕获、管理微服务流量，并提供重放攻击测试能力，支持安全团队进行安全测试。

### 1.3 目标用户
- 安全团队（唯一用户群体）
- 无需角色划分

---

## 2. 功能需求

### 2.1 流量捕获

#### 2.1.1 数据来源
- 通过 Nginx mirror 机制获取流量
- 仅捕获请求数据，不存储响应数据

#### 2.1.2 捕获范围
- **服务数量**：10+ 个微服务
- **协议类型**：REST API
- **环境**：开发环境
- **数据大小**：支持单请求 body 最大 10MB

#### 2.1.3 捕获字段
- 时间戳（精确到毫秒）
- 服务名称（从 URL 第一层路径提取）
- 接口路径（URL Path，保留完整路径）
- 请求方法（GET/POST/PUT/DELETE 等）
- 请求头（Headers）
- 请求体（Body）
- 客户端 IP

#### 2.1.4 数据处理流程
```
Nginx Mirror 流量
    ↓
[原始流量表] （临时存储，定时清理）
    ↓
自动发现模块（提取服务名、接口路径、Method）
    ↓
服务管理：新服务则创建服务记录
接口管理：新接口则创建接口记录（状态 Auto-Complete）
    ↓
去重处理（异步，Celery+Redis）
    ↓
[筛选流量表]（永久保留，挂载到对应接口）
```

#### 2.1.5 流量接收协议
- **接收方式**：HTTP POST 接口接收
- **推送模式**：支持 Nginx mirror 单条推送
- **响应格式**：
  - 成功：HTTP 200，返回 `{"status": "ok"}`
  - 失败：HTTP 400/500，返回错误信息
- **限流保护**：支持基于 IP 的限流，防止高峰期接收端被打爆

### 2.2 服务与接口管理

#### 2.2.1 服务管理
- **服务识别**：从 URL 第一层路径提取服务名（如 `/order-service/api/v1/users` → 服务名为 `order-service`）
- **服务信息字段**：
  - 服务名称（唯一标识）
  - 服务描述
  - 责任人
  - 创建时间
  - 最后活跃时间
- **服务不分组**

#### 2.2.2 接口管理
- **接口定义**：相同 Path + 相同 Method 算一个接口
- **接口路径归一化**：
  - 列表展示：使用归一化路径（如 `/users/{id}`）
  - 详情展示：保留原始完整路径（如 `/users/123`）
- **接口状态**：
  - `Auto-Complete`：自动发现，可手动改为 document
  - `document`：通过 JSON 文档导入，不可修改
  - `deprecated`：废弃接口，30天无流量自动标记或手动标记
- **接口统计字段**：
  - 总请求数（原始流量统计）
  - 去重后流量数（筛选流量统计）
  - 最后请求时间
- **废弃判定**：30天无流量的接口自动标记为 deprecated
- **删除级联**：删除接口时，级联删除该接口下的所有筛选流量和变体流量

#### 2.2.3 接口导入
- 支持 JSON 文档导入 API 定义
- 导入时如接口已存在（Auto-Complete 状态），系统自动更新为 document 状态

### 2.3 流量管理

#### 2.3.1 数据分层

| 数据层级 | 存储内容 | 保留策略 |
|----------|----------|----------|
| 原始流量 | 接收的所有请求（含重复） | 3-7天自动清理，可手动清理 |
| 筛选流量 | 去重后的唯一请求 | 永久保留，可手动删除 |
| 变体流量 | 重放时修改生成的请求 | 永久保留，随筛选流量级联删除 |

#### 2.3.2 去重策略

**参与去重字段**（5个）：
| 字段 | 说明 |
|------|------|
| 服务名称 | 从 URL 提取的第一层路径 |
| 接口路径 | 归一化后的路径（如 `/users/{id}`） |
| 请求方法 | GET/POST/PUT/DELETE 等 |
| 请求头 | 参与去重，**排除**时间、Cookie、Token 相关字段 |
| 请求体 | 完整 Body 内容 |

**去重规则**：
- 以上五个字段完全相同的请求视为重复
- 仅保留首次捕获的请求，其余丢弃
- 去重算法：MD5 哈希
- 处理方式：异步（Celery + Redis 队列）

**请求头排除字段**（不参与去重）：
- 时间相关：`Date`、`X-Request-Time` 等
- Cookie：`Cookie`、`Set-Cookie`
- Token：`Authorization`、`X-Auth-Token`、`X-Token` 等

#### 2.3.3 数据清理策略

**原始流量清理**：
- 清理周期：全局统一，用户可配置（3/5/7/14天）
- 触发方式：定时自动清理 + 手动清理
- 清理方式：物理删除

**筛选流量清理**：
- 默认永久保留
- 支持用户手动删除
- 删除时级联删除其下的变体流量

**接口清理**：
- 30天无流量自动标记 deprecated
- 支持用户手动删除 deprecated 接口
- 删除时级联删除该接口下的筛选流量和变体流量

#### 2.3.4 查询与筛选
- 按服务名称筛选
- 按接口路径筛选（支持归一化路径搜索）
- 按请求方法筛选
- 按时间范围筛选
- 按接口状态筛选（Auto-Complete/document/deprecated）
- 关键字搜索（支持 body 内容搜索）

#### 2.3.5 流量列表展示字段
- 捕获时间
- 服务名称
- 接口路径（展示归一化路径）
- 请求方法
- Body 大小
- Body 预览（前 200 字符）
- 标签

#### 2.3.6 流量详情
- 展示完整的请求信息（所有字段）
- 接口路径展示原始完整路径
- Body 支持格式化展示（JSON/XML 美化）
- 支持复制请求数据
- 展示关联的变体流量列表
- 展示重放历史记录

#### 2.3.7 标签管理
- 支持给流量打标签，如：
  - "已测试"
  - "高危"
  - "待验证"
- 支持按标签筛选
- 支持批量打标签
- 支持批量取消标签

#### 2.3.8 数据导出与导入
- 支持单条/批量导出流量数据
- 导出格式：JSON
- 支持流量数据导入（用于数据恢复或迁移）
- 导入格式：JSON

#### 2.3.9 批量操作
- 批量删除流量
- 批量打标签
- 批量取消标签
- 批量导出
- 批量重放（部分失败时记录失败明细）

#### 2.3.10 全文搜索
- 支持 Body 内容全文搜索
- 使用 PostgreSQL 全文搜索（不引入 Elasticsearch）
- 支持前缀匹配和包含匹配

### 2.4 重放测试

#### 2.4.1 重放目标
用于安全测试，验证系统安全性

#### 2.4.2 重放模式
| 模式 | 说明 |
|------|------|
| 单条重放 | 选择单条流量进行重放 |
| 批量重放 | 选择多条流量批量执行 |
| 按比例重放 | 按设定比例抽样重放 |
| 按时间重放 | 按捕获时间顺序重放 |

#### 2.4.3 请求修改

**可修改内容**：
- 请求体（Body）
- 请求头（Headers）
- 请求 URL
- 请求方法（Method）

**修改方式**（按顺序叠加执行）：
1. **模板变量替换**：支持变量如 `${timestamp}`、`${randomId}`、`${uuid}` 等
2. **字段级修改**：指定 JSON 字段路径修改值，保留其他内容
3. **脚本转换**：支持简单转换脚本（Python/JS 语法）
4. **手动编辑**：在重放前弹出编辑器人工修改

**变体流量存储**：
- 修改后的请求作为"变体流量"持久化存储
- 归属到原始流量所在的接口下
- 存储完整的修改后请求数据（非修改规则）
- 变体流量与筛选流量保留策略一致（永久保留）

#### 2.4.4 重放配置
- **目标地址**：可配置重放的目标地址（支持切换到不同环境）
- **并发控制**：支持设置并发数限制
- **请求间隔**：支持设置请求间隔时间
- **超时设置**：支持设置请求超时时间

#### 2.4.5 重放结果记录
- 响应状态码
- 响应头
- 响应体（限制大小，如最大 1MB）
- 执行时间（毫秒）
- 是否成功标识
- 重放时间戳
- 错误信息（如有）
- **关联变体流量**：记录是对哪个变体流量（或原始筛选流量）的重放
- **结果对比**（可选）：与原响应对比状态码一致性

#### 2.4.6 结果查看
- 重放历史列表
- 单条重放详情
- 成功率统计
- 平均响应时间统计
- 按变体流量查看重放结果

#### 2.4.7 定时重放（待定）
- 支持配置定时重放任务
- 支持 Cron 表达式
- 支持启用/禁用任务

## 3. 非功能需求

### 3.1 性能需求
- 流量捕获吞吐量：支持高峰期流量
- 页面加载时间：列表页 < 2s
- 去重处理：异步处理，不阻塞流量接收

### 3.2 可用性需求
- 内部工具，无需高可用部署
- 支持单机部署

### 3.3 安全需求
- 内部网络使用，无需复杂认证
- 不涉及敏感数据脱敏（已确认无敏感数据）

### 3.4 技术实现
- **后端框架**：FastAPI + Pydantic
- **数据库**：PostgreSQL
- **前端**：Vue
- **异步处理**：Celery + Redis
- **去重算法**：MD5

## 5. 术语表

| 术语 | 说明 |
|------|------|
| 流量 | 指 HTTP 请求数据 |
| 原始流量 | 从 Nginx mirror 接收的所有请求（含重复） |
| 筛选流量 | 经过去重处理后保留的唯一请求 |
| 变体流量 | 基于筛选流量通过修改生成的请求，用于重放测试 |
| 重放 | 将捕获的请求重新发送到目标服务 |
| 去重 | 根据指定字段判断是否重复，仅保留一条 |
| 归一化路径 | 将路径中的变量部分替换为占位符（如 `/users/123` → `/users/{id}`） |
| 服务 | 微服务名称，从 URL 第一层路径提取 |
| 接口 | 唯一的 Path + Method 组合 |
