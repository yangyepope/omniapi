## 二、深度追问 - 关键挑战性问题

### 问题 1：路径归一化的"幻觉陷阱"

**背景**：接口识别依赖 URL 第一层路径作为服务名，同时对 Path 进行归一化（`/users/123` → `/users/{id}`）。

**挑战**：
- 如果微服务采用非标准路由设计（如 `/api/v1/users` 中的 `api` 被识别为服务名），将导致服务爆炸
- 纯数字 ID vs UUID vs 字符串 ID 的归一化规则如何定义？
- `/users/123/orders/456` 应该归一化为 `/users/{id}/orders/{id}` 还是 `/users/{userId}/orders/{orderId}`？

**风险**：错误的归一化将导致接口聚合失败，去重算法失效。

---

### 问题 2：去重算法的"成本黑洞"

**背景**：使用 MD5 哈希对 5 个字段进行去重，支持单请求 body 最大 10MB。

**挑战**：
- **计算成本**：高峰期流量 QPS 是多少？10MB body × N QPS 的 MD5 计算将在 CPU 上产生多大压力？
- **存储成本**：Redis 中需要存储多少 MD5 指纹？TTL 策略是什么？
- **内存风险**：如果 Redis 容量不足，去重服务将出现什么行为？降级还是阻塞？

**风险**：未经评估的去重策略可能在流量洪峰时拖垮整个系统。

---

### 问题 3：变体流量的"数据孤岛"

**背景**：变体流量是"修改后的完整请求数据"，永久保留，挂载在筛选流量下。

**挑战**：
- 如果原始筛选流量被手动删除，其下的变体流量将级联删除——这意味着用户可能在不知情的情况下丢失大量测试用例
- 变体流量与筛选流量的关系是"挂载"而非"继承"，当原始请求的结构发生变化（如上游接口版本迭代），历史变体是否仍然有效？
- 变体流量支持"脚本转换"，脚本版本管理如何设计？

**风险**：数据级联删除可能导致测试资产意外丢失，缺乏版本控制的脚本将产生维护噩梦。

---

### 问题 4：重放测试的"安全反噬"

**背景**：系统用于安全测试，支持修改请求后重放到目标服务。

**挑战**：
- **环境隔离**：如何防止误操作将重放流量发送到生产环境？
- **级联重放**：如果重放的请求会触发下游服务的 Webhook/回调，如何避免对第三方系统造成影响？
- **敏感数据残留**：虽然声明"无敏感数据"，但如果捕获的请求中包含测试用户的真实凭证，重放时如何脱敏？

**风险**：安全测试工具本身可能成为安全漏洞的源头。

---

### 问题 5：异步任务的"可观测性盲区"

**背景**：使用 Celery + Redis 进行异步去重，支持批量操作。

**挑战**：
- **任务丢失**：如果 Celery Worker 崩溃，正在处理的去重任务如何恢复？
- **重复消费**：Redis 队列如何保证"恰好一次"处理？
- **批量重放的部分失败**："部分失败时记录失败明细"——这个明细如何展示？失败率超过阈值时是否自动停止？
- **死信队列**：处理失败的消息最终去向何处？

**风险**：异步架构的故障模式比同步更隐蔽，缺乏可观测性将导致问题难以定位。

## 三、需求补全建议

### 3.1 功能性需求补全

| 模块 | 缺失场景 | 补全需求 |
|------|----------|----------|
| **流量捕获** | 格式异常数据 | 增加"无效流量隔离区"，存储解析失败的原始数据供人工审查，TTL 7天 |
| **去重处理** | 哈希碰撞处理 | MD5 碰撞概率极低但不为零，需增加"二次校验"机制：哈希冲突时对比完整字段 |
| **接口管理** | 接口合并/拆分 | 支持手动合并误识别的接口（如将 `/users/{id}` 和 `/user/{id}` 合并） |
| **变体管理** | 变体版本控制 | 变体支持版本历史，可回滚到任意版本 |
| **重放执行** | 断路器机制 | 当目标服务连续失败超过阈值（如 10 次/1分钟），自动暂停重放并告警 |
| **批量操作** | 任务恢复 | 批量任务支持"断点续传"，可查询进度并在失败处继续执行 |
| **数据清理** | 清理前确认 | 手动清理前需展示"将删除 X 条记录，涉及 Y 个接口"的确认弹窗 |
| **导入导出** | 格式兼容性 | JSON Schema 版本控制，导入时校验并提示版本不匹配 |

### 3.2 用户路径闭环

```
流量捕获 → 服务发现 → 接口归一化 → 去重筛选 → 打标签分类 → 生成变体 → 重放测试 → 结果分析 → 导出报告
   ↑___________________________________________________________________________________________|
                                    (支持从任意节点重新开始)
```

## 四、API 契约初稿（核心接口）

### 4.1 流量接入

```
POST /v1/ingestion/flow          # 接收 Nginx Mirror 流量
```

**错误码**：
| 状态码 | 错误码 | 说明 |
|--------|--------|------|
| 429 | `RATE_LIMIT_EXCEEDED` | IP 限流触发 |
| 400 | `INVALID_PAYLOAD` | 请求体格式错误 |
| 413 | `PAYLOAD_TOO_LARGE` | Body 超过 10MB |

### 4.2 服务管理

```
GET    /v1/services                    # 服务列表
POST   /v1/services                    # 手动创建服务
GET    /v1/services/{name}             # 服务详情
PUT    /v1/services/{name}             # 更新服务
DELETE /v1/services/{name}             # 删除服务（级联删除接口）
GET    /v1/services/{name}/stats       # 服务统计
```

### 4.3 接口管理

```
GET    /v1/services/{svc}/interfaces          # 接口列表
POST   /v1/services/{svc}/interfaces/import   # JSON 导入
GET    /v1/interfaces/{id}                    # 接口详情
PUT    /v1/interfaces/{id}                    # 更新接口
DELETE /v1/interfaces/{id}                    # 删除接口
POST   /v1/interfaces/{id}/merge              # 合并接口（高级功能）
```

### 4.4 流量管理

```
GET    /v1/flows/raw                # 原始流量查询
DELETE /v1/flows/raw                # 批量清理原始流量
GET    /v1/interfaces/{id}/flows    # 筛选流量列表
GET    /v1/flows/{id}               # 流量详情
DELETE /v1/flows/{id}               # 删除流量（级联删除变体）
POST   /v1/flows/batch/tag          # 批量打标签
POST   /v1/flows/batch/export       # 批量导出
POST   /v1/flows/import             # 导入流量
POST   /v1/flows/search             # 全文搜索
```

### 4.5 变体管理

```
GET    /v1/flows/{id}/variants      # 变体列表
POST   /v1/flows/{id}/variants      # 创建变体
GET    /v1/variants/{id}            # 变体详情
PUT    /v1/variants/{id}            # 更新变体
DELETE /v1/variants/{id}            # 删除变体
POST   /v1/variants/{id}/replay     # 执行重放（单条）
```

### 4.6 重放执行

```
POST   /v1/replay/batch             # 批量重放
GET    /v1/replay/tasks/{id}        # 任务状态查询
GET    /v1/replay/tasks/{id}/results # 重放结果列表
DELETE /v1/replay/tasks/{id}        # 取消任务
POST   /v1/replay/tasks/{id}/retry  # 重试失败项
```
