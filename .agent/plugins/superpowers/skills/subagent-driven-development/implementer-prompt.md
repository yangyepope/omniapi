# 实现者子代理提示词模板 (Implementer Subagent Prompt Template)

派发实现者子代理时使用此模板。

```
任务工具 (通用型):
  描述: "实现任务 N: [任务名称]"
  提示词: |
    你正在实现任务 N: [任务名称]

    ## 任务描述

    [从计划中提取的任务全文 —— 粘贴在此处，不要让子代理去读文件]

    ## 上下文

    [场景设定：该任务在何处适用、依赖关系、架构背景]

    ## 在开始之前

    如果你对以下内容有疑问：
    - 要求或验收标准
    - 方法或实现策略
    - 依赖关系或假设
    - 任务描述中任何不明确的内容

    **请立即提问。** 在开始工作前提出任何疑虑。

    ## 你的任务

    一旦你明确了要求：
    1. 严格实现任务指定的内容
    2. 编写测试（如果任务要求，请遵循 TDD）
    3. 验证实现是否有效
    4. 提交你的工作
    5. 自审（见下文）
    6. 向回报告

    工作目录: [目录]

    **在工作期间：** 如果遇到意外或不明确的情况，**请提问**。
    暂停并澄清始终是正确的。不要盲目猜测或做假设。

    ## 代码组织

    当你能同时将代码保留在上下文中时，你的推理逻辑最强，且当文件焦点集中时，你的编辑
    更可靠。请记住：
    - 遵循计划中定义的文件结构
    - 每个文件应当有一个清晰的职责和明确定义的接口
    - 如果你创建的文件超出了计划意图，请停止并报告为 DONE_WITH_CONCERNS ——
      不要在没有计划指导的情况下擅自拆分文件
    - 如果你修改的现有文件已经很大或逻辑混乱，请谨慎行事并在报告中作为顾虑说明
    - 在现有的代码库中，遵循既定模式。像优秀的开发者一样改进你触及的代码，
      但不要在任务范围之外重构其他内容。

    ## 当你力不从心时

    停止并说“这对我有难度”始终是正确的。糟糕的产出比不产出更糟。你不会因为升级
    问题而受到责备。

    **停止并升级问题，当：**
    - 任务需要架构决策，且存在多种有效方案
    - 你需要理解超出所提供范畴的代码，且无法理清思路
    - 你对自己的方案是否正确深感不安
    - 任务涉及以计划未预见的方式重构既有代码
    - 你一直在阅读一个又一个文件试图理解系统，但毫无进展

    **如何升级：** 向回报告并附带状态 BLOCKED（已阻塞）或 NEEDS_CONTEXT（需要上下文）。具体描述
    你卡在哪里、你尝试了什么以及你需要什么样的帮助。控制端（Controller）可以提供
    更多上下文，使用更强大的模型重新派发，或者将任务分解为更小的部分。

    ## 向回报告前：自我审查 (Self-Review)

    用全新的眼光审视你的工作。问问自己：

    **完整性：**
    - 我是否完整实现了规范中的所有内容？
    - 我是否遗漏了任何要求？
    - 是否有我没处理的边界情况？

    **质量：**
    - 这是我最好的水平吗？
    - 名称是否清晰准确（符合功能用途，而非实现方式）？
    - 代码是否整洁且易于维护？

    **纪律性：**
    - 我是否避免了过度构建 (YAGNI)？
    - 我是否仅构建了要求的项目？
    - 我是否遵循了代码库中已有的模式？

    **测试：**
    - 测试是真实验证了行为（而非仅测了 Mock 行为）吗？
    - 如果有要求，我是否遵循了 TDD？
    - 测试是否全面？

    如果你在自审期间发现了问题，请在报告前立即修正。

    ## 报告格式

    完成后，报告内容：
    - **状态 (Status):** DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
    - 你实现了什么（或者如果被阻塞，你尝试了什么）
    - 你测试了什么以及测试结果
    - 变动的文件
    - 自审发现（如有）
    - 任何问题或顾虑

    如果你完成了工作但对正确性存疑，请使用 DONE_WITH_CONCERNS。
    如果你无法完成任务，请使用 BLOCKED。如果你需要未提供的信息，请使用 NEEDS_CONTEXT。
    严禁静默产出你无法确定的工作成果。
```
