# 完成前验证 (Verification Before Completion)

## 概览

在没有经过验证的情况下宣称工作已完成是极大的失职，而非高效。

**核心原则：** 始终证据先行，断言在后。

**违反此规则的字面意思即是违反了此规则的精神。**

## 铁律 (The Iron Law)

```
在没有新鲜的验证证据之前，严禁做出任何完成状态的断言。
```

如果你在当前消息中还没有运行过验证命令，你就不能宣称它已通过。

## 网关功能 (The Gate Function)

```
在宣称任何状态或表达满意之前：

1. 识别 (IDENTIFY): 哪个命令可以证明这一断言？
2. 运行 (RUN): 执行完整的命令（新鲜的、完整的）
3. 读取 (READ): 查看全部输出，检查退出代码，计算失败项数量
4. 验证 (VERIFY): 输出是否证实了该断言？
   - 如果 否 (NO): 陈述实际状态并附带证据
   - 如果 是 (YES): 陈述断言内容并附带证据
5. 只有在完成上述步骤后: 才能做出结论断言

跳过任何步骤 = 撒谎，而非验证
```

## 常见失败案例

| 断言内容 | 需要什么证据 | 不足以为证的情况 |
|-------|----------|----------------|
| 测试通过 | 测试命令输出：0 失败 | 上次的运行结果，“应该能过” |
| Linter 清爽 | Linter 输出：0 错误 | 部分检查，推测 |
| 构建成功 | 构建命令：退出代码 0 | Linter 已过，日志看起来不错 |
| Bug 已修复 | 测试原始症状：已通过 | 代码已改，假设已修好 |
| 回归测试有效 | 红-绿循环已验证 | 测试通过了一次 |
| 代理已完成 | VCS diff 显示了变更 | 代理报告“成功” |
| 要求已达成 | 逐项核对清单 | 测试已通过 |

## 警示信号 —— 立即停止

- 使用“应该”、“大概”、“似乎”等词汇。
- 在验证前表达满意感（“太棒了！”、“完美！”、“完成了！”等）。
- 在没有验证的情况下准备提交/推送/创建 PR。
- 盲目相信代理的成功报告。
- 依赖于部分验证。
- 产生“就这一次”的想法。
- 因为疲劳而想快点结束工作。
- **任何暗示成功但并未实际运行验证命令的措辞。**

## 防止辩解 (Rationalization Prevention)

| 借口 | 现实 |
|--------|---------|
| “现在应该行了” | 请立即运行验证 |
| “我有信心” | 信心 ≠ 证据 |
| “就这一次” | 绝无例外 |
| “Linter 过过了” | Linter ≠ 编译器 |
| “代理报成功了” | 请独立验证 |
| “我累了” | 疲惫 ≠ 借口 |
| “部分检查就够了” | 部分通过证明不了任何事 |
| “不同的措辞所以规则不适用” | 精神重于字面意思 |

## 关键模式

**测试：**
```
✅ [运行测试命令] [看到: 34/34 通过] “所有测试已通过”
❌ “现在应该能过了” / “看起来是正确的”
```

**回归测试 (TDD 红-绿循环):**
```
✅ 编写测试 ——> 运行（通过） ——> 撤销修复 ——> 运行（必须失败） ——> 恢复修复 ——> 运行（通过）
❌ “我已经写了一个回归测试”（在没有进行红-绿循环验证的情况下）
```

**构建：**
```
✅ [运行构建] [看到: 退出代码 0] “构建已通过”
❌ “Linter 已过” （Linter 不会检查编译错误）
```

**要求满足情况：**
```
✅ 重新阅读计划 ——> 创建核对清单 ——> 逐一验证 ——> 报告缺漏或完成情况
❌ “测试已通过，该阶段已完成”
```

**代理委派：**
```
✅ 代理报告成功 ——> 检查 VCS diff ——> 验证变更 ——> 报告实际状态
❌ 盲目相信代理报告
```

## 为什么这很重要

来自 24 次失败记忆的教训：
- 你的类比伙伴说“我不相信你” —— 信任破裂。
- 发布了未定义的函数 —— 会在运行时崩溃。
- 发布了缺失要求的内容 —— 交付了不完整的特性。
- 在错误的“完成”状态上浪费了时间 ——> 重新导向 ——> 返工。
- 违反了规则：“诚实是核心价值观。如果你撒谎，你将被替代。”

## 何时应用

**在以下情况之前，必须始终应用：**
- 任何形式的关于成功/完成的断言。
- 任何满意感的表达。
- 任何关于工作状态的正向陈述。
- 提交、创建 PR、标记任务完成之前。
- 进入下一个任务之前。
- 委派给其他代理之前。

**规则适用于：**
- 准确的措词。
- 释义和近义词。
- 暗示成功的倾向。
- 任何暗示完成或正确性的沟通。

## 底线原则

**验证没有捷径。**

运行命令。读取输出。然后才能断言结果。

这是不可逾越的底线。
