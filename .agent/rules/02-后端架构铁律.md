# 02-后端架构铁律 (Backend Core)

本文档定义了 OmniAPI 后端的统一架构标准与技术选型，作为 `ecc/python` 通用规则的强力补充。

---

## 一、 核心架构：整洁架构 (Clean Architecture)

AI 助手在设计系统级逻辑时，必须遵循以下层级隔离：
- **领域层 (Domain)**: 存放核心实体与业务逻辑，不依赖任何框架。
- **服务层 (Service)**: 负责编排业务流程，处理事务边界。
- **接口层 (Route/Controller)**: 仅负责请求分发与响应格式转化，**严禁**直接编写原生 SQL。
- **持久层 (Repository/CRUD)**: 使用 **SQLModel / SQLAlchemy 2.0+** 实现数据访问劫持。

### 依赖注入 (DI)
- 深度利用 FastAPI 的 `Depends` (支持 Python 3.10+ 的 `Annotated` 语法)。
- 所有的外部服务（Redis, DB, Email）必须通过 DI 注入，严禁在函数内硬编码实例化。

---

## 二、 数据验证与类型安全 (Pydantic v2)

- **极致强类型**: 强制对所有函数参数及返回值进行类型标注，代码必须通过 `mypy` 严格检查。
- **Pydantic v2 核心**: 使用 Pydantic v2 执行从入参到出参的端到端验证，绝对禁止使用弱类型的 `dict` 传递核心数据。

---

## 三、 异常与响应规范

- **全局异常拦截**: 禁止使用裸露的 `try-except Exception`。所有业务错误必须抛出自定义领域异常。
- **统一响应格式**: 所有 API 返回必须结构化，包含 `code`, `message`, `details` 或数据负载。
- **安全性**: 严禁向外暴露内部堆栈信息 (Traceback)。

---

## 四、 框架特定稳定性 (Stability Patches)

### 1. LangChain 规范
- **批量 I/O**: `BaseChatMessageHistory` 的子类必须实现 `add_messages` 批量方法。
- **序列化**: 统一使用 `message_to_dict` 保持 MetaData 完整。

### 2. Streamlit 异步补丁
- **Event Loop 校验**: 在初始化具备异步 I/O 的组件时，必须执行 `asyncio.get_running_loop()` 校验，防止 "Event loop is closed" 报错。
- **单例化**: 使用 `st.cache_resource` 维护单例生命周期。

---

## 五、 极致注释标准

- **同步中文标准**: 所有的 `Google Style Docstrings` 必须使用简体中文。
- **Why over What**: 对复杂异步逻辑，执行“**逐行中文注释**”，重点解释设计意图。
