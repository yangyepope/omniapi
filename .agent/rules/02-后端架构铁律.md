# 02-后端架构铁律 (Backend Core V8.2 Sync)

本文档定义了 OmniAPI 后端的统一架构标准与技术选型，并在 **2026-04-03** 根据 10 万并发实战经验进行了原子一致性加固。

---

## 一、 核心架构：整洁架构 (Clean Architecture)

AI 助手在设计系统级逻辑时，必须遵循以下层级隔离：
- **领域层 (Domain)**: 存放核心实体与业务逻辑，不依赖任何框架。
- **服务层 (Service)**: 负责编排业务流程，处理事务边界。
- **持久层 (Repository/CRUD)**: 
    - 统一使用 **SQLModel / SQLAlchemy 2.0+**。
    - **严禁**直接编写字符串 SQL 代码（除非极其复杂的读性能优化）。
    - **强制**在写操作中使用 SQLAlchemy Core Expressions 以保证原子性。

---

## 二、 极致强类型 (Type Safety)

- **强类型标注**: 所有的函数参数及返回值必须显式标注类型。
- **Pydantic v2**: 执行端到端的验证。严禁使用 `dict` 传递核心业务实体。

---

## 三、 异常与响应规范

- **全局异常拦截**: 所有业务错误必须抛出自定义异常，由全局 Handler 捕获。
- **禁止堆栈外泄**: 严禁向 API 消费者返回 Traceback。

---

## 四、 后端稳定性补丁 (Stability Patches)

### 1. LangChain / Celery 规范
- **异步安全**: 在 Celery 任务中必须使用专用的异步连接池配置。
- **幂等性**: 所有的 Worker 任务必须具备幂等性（利用 `on_conflict` 实现）。

---

## 六、 高并发原子一致性 (High-Sensitivity Atomicity)

**本章节是 OmniAPI 处理海量流量治理的核心物理底座：**

### 1. 锁序层级协议 (Lock Hierarchy Protocol) 
当业务涉及多表联合更新时，必须遵循单一方向的物理持锁逻辑：
- **路径要求**: **[SystemModule] -> [ApiEndpoint] -> [FilteredFlow]**。
- **违规警告**: 严禁以交替顺序启动事务，任何“无序竞争”都将导致物理死锁。

### 2. 数据库级原子性更新 (Database-Level Atomicity)
- **计数策略**: 严禁在 Python 层执行 `old_val + 1`，必须使用 SQL 累加表达式：`Model.field + 1`。
- **Upsert 标准**: 所有的“获取或创建”逻辑必须绑定 `ON CONFLICT DO UPDATE` 原子指令，保证 10 万级并发下无重复记录。

### 3. 持久化边界与事务漂移防御
- **事务内 (Hot-IO)**: 仅执行物理写指令，保持持锁时长 < 10ms。
- **事务外 (CPU-Block)**: 哈希运算、归一化、JSON 解析必须在 `engine.begin()` 外部完成。

### 4. 弹性死锁自愈 (Deadlock Backoff)
高频死锁（OperationalError）必须通过 **随机抖动指数退避 (Jittered Backoff)** 进行自愈重试，严禁直接向用户报错。
