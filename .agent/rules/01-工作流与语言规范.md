# 01-工作流与语言规范 (V2)

本文档定义了 SecurityPlatform 项目中 AI 助手的全局行为准则、语言强制规范及操作日志同步规则。本规则作为 `ecc` (Enhanced Coding Capability) 和 `superpowers` 插件的**核心基础**，具有最高优先级。

---

## 一、 语言规则 (Language Rules)

在所有 agent 会话中，输出内容必须使用**简体中文**，包括：
- 代码注释（如用户未特别指明语言）
- 解释说明
- 错误诊断
- 计划文档（task.md、implementation_plan.md、walkthrough.md 等）
*技术术语（如函数名、命令、代码本身）保持原文，仅说明性文字翻译为中文。*

### AI 助手强制执行指令 (AI Execution Directives)
- **默认开启全局注释**：AI 在任何场景下新建文件、修改代码或生成代码片段时，必须**默认且主动地**遵循 `global-commenter` 和 `line-commenter` 的标准。
- **注释粒度要求**：对核心业务逻辑强制实行“**逐行中文注释**”，重点解释“Why over What”。严禁因为“代码简单”或“未被显式要求”而省略注释输出。

## 二、 自动操作日志记录 (Operation Logging)

每当 AI 助手完成一次实质性的操作（包括但不限于代码修改、文件创建、命令运行、Git 提交等），**必须**立即更新记录。

### 强制要求
1. **唯一性**：操作完成后，在告知用户之前，优先更新记录。**严禁覆盖旧的记录文件**，应根据任务内容创建唯一的文件名。
2. **命名格式**：单服务任务落 `{服务}/document/walkthroughs/walkthrough_[任务描述]_[日期].md`（如 `backend/document/walkthroughs/`），跨服务任务落根 `document/walkthroughs/`。请勿将日志文件平铺在 `document/` 根、服务根目录或项目最外围根目录（文档树总索引见 `document/README.md`）。
3. **格式要素**：
   - 标题必须包含 `[YYYY-MM-DD HH:mm:ss]`。
   - 逻辑必须分层（操作描述、改动详情、验证结果）。
   - 使用 Markdown 检查清单 `- [x]` 记录验证。
4. **归档要求**：记录应按时间顺序保留在项目目录中，作为项目的历史证据。

> [!IMPORTANT]
> 记录日志不是可选的，而是工作流程中不可分割的一部分。它旨在让用户随时掌握项目的历史变迁。

## 三、 计划文档同步 (Planning Documentation Sync)

AI 助手在执行复杂任务时生成的计划类文档（如任务清单、实施方案等），**必须**同步保存到 `document/plans/` 文件夹中（单服务任务落 `{服务}/document/plans/`）。

### 强制要求
1. **命名规范**: `document/plans/YYYYMMDD_[任务描述]_[文档类型].md`。
   - 例如: `document/plans/20260319_会话持久化_任务清单.md`。
2. **即时更新**: 计划文档一旦在内存或私有目录中生成或修改，应立即按照此规范同步到 `plans/` 文件夹中。
3. **其余文档类别**（`changelog/`、`bugs/`、`features/`、`adr/`、`ops/`、`architecture/`）为项目级,只在根 `document/` 维护,规则与模板见 `document/README.md` 及各目录 `_TEMPLATE.md`。

## 四、 自动化测试凭据规范 (Automated Testing Credentials)

为了保证 UI / E2E 自动化测试的连续性，AI 助手必须遵循以下凭据管理协议：

1. **唯一凭据源**：必须优先读取项目最外层根目录下的 [.env](file:///root/security-platform/.env) 文件。
2. **关键变量**：
   - `FIRST_SUPERUSER`：自动化测试登录账号
   - `FIRST_SUPERUSER_PASSWORD`：自动化测试登录密码
3. **操作流程**：
   - 在首次运行 `/e2e` 或 Playwright 测试前，检查上述变量。
   - 若变量缺失或测试返回 401，主动提醒用户补充根目录 `.env`，不得随意填写 Mock 数据。
4. **Session 维护**：在凭据可用时，运行 `npx playwright test tests/auth.setup.ts` 以持久化登录状态。
